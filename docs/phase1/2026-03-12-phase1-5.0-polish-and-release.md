# Phase 1 - 1-5.0 Polish & Release

**阶段**: `1-5.0`  
**优先级**: `P1`  
**前置条件**: `1-4.0` 全部完成  
**对应问题**: 即使完整 run 已经成立，如果没有数值打磨、检视能力、测试覆盖率收口与发布资产整理，项目仍然不具备对外可交付的 `v0.1.0` 品质。

---

## 1. 阶段目标

在完整 run 成立后，完成数值平衡、检视模式、覆盖率收口、Bug 清零与发布准备，交付 Phase 1 的正式出口版本 `v0.1.0`。

完成标准：

1. `core` 覆盖率达标并可自动失败。
2. 检视模式让玩家能解释战斗与 build。
3. P0/P1 Bug 收口。
4. 发布工件与基础 README/运行说明齐备。

---

## 2. 当前问题

1. 当前系统即使能通关，也可能仍然缺少战术可解释性。
2. 没有检视模式时，很多怪物/装备/状态信息对玩家是黑箱。
3. 没有回归与覆盖率收口，`v0.1.0` 无法建立可信质量基线。
4. 没有发布工件与运行说明，对外不可分发。

### 2.1 本阶段冻结口径

1. 覆盖率目标不再继续上调，而是固定收口到：
   - `core` 总体行覆盖率 `>= 80%`
   - 关键包行覆盖率 `>= 85%`
2. 检视模式默认按键固定为 `x`。
3. Phase 1 只发布桌面版可运行工件。

---

## 3. 范围与非目标

### 3.1 范围

1. 数值平衡与通关时间调优
2. 检视模式
3. 覆盖率与回归门禁收口
4. P0/P1 Bug 修复
5. 发布工件与运行说明

### 3.2 非目标

1. 不在本阶段继续扩系统或内容池。
2. 不把大规模重构伪装成“打磨”。
3. 不在本阶段引入新职业、新资源系统或大型 UI 重做。

---

## 4. 技术方案

### 4.1 数值平衡

本阶段的数值调优必须基于固定 run 样本，而不是感觉式修改。

建议做法：

1. 固定 `3-5` 组 seed
2. 记录：
   - 通关时间
   - 楼层死亡点
   - 资源消耗
   - 装备与天赋使用频率
3. 只调整：
   - 怪物数值
   - 经验曲线
   - 掉落节奏
   - 天赋消耗/冷却

### 4.2 检视模式

建议文件：

```text
client/src/main/kotlin/com/ktome/client/screen/InspectMode.kt
client/src/main/kotlin/com/ktome/client/ui/TooltipPanel.kt
```

最低要求：

1. 可查看怪物名称、HP、主要属性、关键状态
2. 可查看物品名称、类型、加成效果
3. 不要求完整百科，只要求实时解释当前场上对象

### 4.3 回归与覆盖率收口

必须补齐：

1. `:core:jacocoTestCoverageVerification` 最终规则
2. 冒烟测试清单
3. 关键 seed 的手动回归记录模板

### 4.4 发布准备

最小交付物：

1. 可运行桌面 jar 或打包产物
2. README 中的运行说明
3. 版本号 `v0.1.0`
4. 已知限制清单

## 6. 测试与自证

### 6.1 必测内容

1. 所有 `core` 模块回归测试全部通过
2. 关键包覆盖率达到最终阈值
3. 检视模式的手动白盒步骤
4. 通关与死亡两条结算链路完整回归

### 6.2 覆盖率门禁

1. `core` 总体行覆盖率 `>= 80%`
2. `combat / map / talent / item / save` 关键包行覆盖率 `>= 85%`

### 6.3 自动化命令

```bash
./gradlew preReleaseAcceptance
```

如需拆分调试，等价命令为：

```bash
./gradlew clean test
./gradlew headlessSmoke
./gradlew clientSmoke
./gradlew jacocoTestReport
./gradlew :core:jacocoTestCoverageVerification
./gradlew :client:releaseDesktopDist
```

Nightly 扩展验证保持独立：

```bash
./gradlew longRunLab
```

### 6.4 白盒验证

固定白盒验证步骤：

1. 开局新游戏并完成一次完整 run
2. 在中途使用检视模式查看怪物与物品信息
3. 验证：
   - 4 个天赋均存在明确战术价值
   - 通关耗时落在 `30-60` 分钟区间
   - 死亡与通关结算都正常
4. 使用发布产物独立运行一次

---

## 7. 出口门禁

1. `./gradlew test` 全绿
2. `./gradlew :core:jacocoTestCoverageVerification` 通过
3. `core` 总体覆盖率 `>= 80%`
4. 检视模式可解释场上关键实体
5. 无未收口的 P0/P1 Bug
6. 可生成并运行 `v0.1.0` 发布工件
7. `preReleaseAcceptance` 的报告与发布工件可归档

---

## 8. 风险与止损

1. 风险：把“平衡”做成无限期调参。  
   止损：只围绕固定 seed 样本与通关时长目标收口。
2. 风险：覆盖率只追数字，不补关键分支。  
   止损：关键包阈值高于总体阈值，且必须保留失败门禁。
3. 风险：README 与发布工件脱节。  
   止损：用发布产物独立跑一次作为最终验收。
4. 风险：检视模式信息源不一致。  
   止损：信息必须直接来自运行时权威状态，而不是 UI 拼接缓存。
