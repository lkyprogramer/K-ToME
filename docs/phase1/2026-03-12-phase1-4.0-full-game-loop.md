# Phase 1 - 1-4.0 Full Game Loop

**阶段**: `1-4.0`  
**优先级**: `P1`  
**前置条件**: `1-3.0` 全部完成  
**对应问题**: 在战斗、物品、天赋分别成立之后，仍然缺少“从开局到结算”的整局闭环；必须把多层地牢、Boss、存档、胜负判定和菜单串起来，Phase 1 才从系统集合变成一款完整可玩的游戏。

---

## 1. 阶段目标

把已经实现的探索、战斗、成长系统串成一条完整 run：

`主菜单 -> 新游戏 -> 5 层推进 -> 楼层切换 -> Boss 战 -> Victory / Game Over -> 存档恢复`

完成标准：

1. 5 层地牢可上下楼切换。
2. 第 5 层 Boss 与普通怪物循环分离。
3. 存档、读档、自动存档与死亡删档成立。
4. 主菜单与胜负画面可驱动整局生命周期。
5. 整局 run 可以从开局推进到结算。

---

## 2. 当前问题

1. 前三个阶段即便完成，也仍然只是局部切片。
2. 没有多层推进时，Boss 与通关目标不存在。
3. 没有存档时，运行时状态不可恢复。
4. 没有主菜单与结算画面，产品形态仍不完整。

### 2.1 本阶段冻结口径

1. 地牢层数固定为 `5`。
2. 存档采用单槽 JSON 方案。
3. 死亡默认执行 `Permadeath` 删档。
4. 楼层切换自动存档。
5. Boss 只要求一个 Phase 1 可通关版本，不追求复杂多阶段机制。

---

## 3. 范围与非目标

### 3.1 范围

1. 楼梯与多层地牢管理
2. 第 5 层 Boss
3. 属性分配与天赋分配入口
4. 存档/读档/自动存档/删档
5. Game Over / Victory / Main Menu

### 3.2 非目标

1. 不在本阶段实现 Adventure 模式或多存档位。
2. 不在本阶段实现复杂剧情系统。
3. 不在本阶段实现云存档或跨平台存档同步。
4. 不在本阶段引入第二个 Boss 或额外结局分支。

---

## 4. 技术方案

### 4.1 多层地牢与楼梯

建议文件：

```text
core/src/main/kotlin/com/ktome/core/dungeon/DungeonManager.kt
core/src/main/kotlin/com/ktome/core/dungeon/FloorState.kt
core/src/test/kotlin/com/ktome/core/dungeon/DungeonManagerTest.kt
```

冻结口径：

1. 楼梯切换由 `DungeonManager` 统一处理。
2. 上下楼后必须恢复正确楼层状态、实体布局与玩家位置。
3. 不允许把楼层切换逻辑散落在 `client` screen 中。

### 4.2 Boss 与结算

建议文件：

```text
game/src/main/resources/data/boss.yaml
game/src/main/kotlin/com/ktome/game/factory/BossFactory.kt
core/src/main/kotlin/com/ktome/core/run/RunOutcome.kt
client/src/main/kotlin/com/ktome/client/screen/VictoryScreen.kt
client/src/main/kotlin/com/ktome/client/screen/GameOverScreen.kt
```

冻结口径：

1. Boss 是第 5 层唯一强制结算目标。
2. 结算状态由 `core` 明确表达为运行结果，不由 UI 猜测。

### 4.3 存档系统

建议文件：

```text
core/src/main/kotlin/com/ktome/core/save/SaveManager.kt
core/src/main/kotlin/com/ktome/core/save/SaveSnapshot.kt
core/src/test/kotlin/com/ktome/core/save/SaveManagerTest.kt
```

冻结口径：

1. 保存格式采用 JSON。
2. 保存对象必须显式版本化。
3. 死亡删档是规则，不是 UI 约定。
4. 恢复时必须还原：
   - 玩家属性
   - 楼层状态
   - 背包/装备
   - 冷却与资源
   - 关键 run 元数据

### 4.4 主菜单与生命周期

建议文件：

```text
client/src/main/kotlin/com/ktome/client/screen/MainMenuScreen.kt
client/src/main/kotlin/com/ktome/client/GameApp.kt
```

冻结口径：

1. `新游戏 / 继续 / 退出` 三个入口明确。
2. 没有存档时 `继续` 必须置灰或不可选。
3. 通关与死亡都必须可回到主菜单。

   - `RunOutcomeTest.kt`


### 6.5 白盒验证

固定白盒验证步骤：

1. 进入主菜单并开始新游戏
2. 推进到下一层并确认可连续切换到第 5 层
3. 使用 `Ctrl+S` 手动存档并重启游戏
4. 选择 `继续` 并确认状态恢复
5. 到第 5 层击杀 Boss，确认进入 `Victory`
6. 另开一局死亡，确认进入 `Game Over` 且存档被删除

## 8. 风险与止损

1. 风险：把存档做成 UI 驱动，导致状态不完整。  
   止损：所有 run 状态以 `SaveSnapshot` 为中心表达。
2. 风险：楼层切换丢失实体与冷却状态。  
   止损：增加楼层切换后再加载的回归测试。
3. 风险：Boss 逻辑与普通怪物 AI 分叉过大。  
   止损：Boss 仍尽量复用现有战斗/天赋/AI 基础设施。
4. 风险：Victory / Game Over 只做画面，不做运行结果归档。  
   止损：`RunOutcome` 必须是 core 层概念。
