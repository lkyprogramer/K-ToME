# Phase 1 1-1.0 Verification Checklist

## 1. Automated Verification

If Gradle cannot resolve remote artifacts because of TLS or proxy issues, bootstrap the local repository first:

```bash
./scripts/bootstrap-deps.sh
```

This bootstrap step prepares both the local Maven repository under `.bootstrap/m2` and the matching Gradle distribution declared by `gradle/wrapper/gradle-wrapper.properties`.

If the change touches dependency versions, build scripts, or bootstrap logic, use the matching offline bootstrap path:

```bash
./scripts/verify-bootstrap.sh
./scripts/verify-bootstrap.sh --smoke
```

- `./scripts/verify-bootstrap.sh` is the full offline bootstrap verify path; CI may add `--clean` when it needs to rebuild bootstrap artifacts from a cold state.
- `./scripts/verify-bootstrap.sh --smoke` is the fast PR smoke path that keeps the isolated `.bootstrap/gradle-user-home` contract without rerunning the full aggregate test suite.

Run the following commands from the project root:

```bash
./gradlew test
./gradlew :core:test
./gradlew jacocoTestReport
./gradlew :core:jacocoTestCoverageVerification
```

Expected outcomes:

1. `test` succeeds.
2. `:core:test` succeeds.
3. `jacocoTestReport` generates reports under:
   - `build/reports/jacoco/test/html/index.html`
   - `core/build/reports/jacoco/test/html/index.html`
4. `:core:jacocoTestCoverageVerification` succeeds.
5. If `.bootstrap/m2` exists, the build should prefer it before remote repositories.
6. `verify-bootstrap.sh` must execute with the bootstrapped Gradle distribution and an isolated `.bootstrap/gradle-user-home`, rather than relying on a prewarmed `~/.gradle` cache.
7. Pull request CI should use `./scripts/verify-bootstrap.sh --smoke`; `main` and manual runs may use `./scripts/verify-bootstrap.sh --clean` to force a fresh full offline bootstrap verify.

## 2. Manual White-Box Verification

Launch the desktop client:

```bash
./gradlew :client:run
```

Controls:

1. `QWEASDZC` for 8-direction movement
2. Arrow keys for 4-direction movement
3. `Home`, `End`, `PageUp`, `PageDown` for diagonals
4. Numpad `1-9` (without `5`) for 8-direction movement

Expected outcomes:

1. The window opens at an `80x50` ASCII dungeon presentation size.
2. The player `@` starts on a walkable floor tile inside the BSP dungeon.
3. The player cannot move through walls.
4. The field of view updates after every successful move.
5. Unexplored tiles remain hidden; explored but currently unseen tiles stay dimmed.
6. The viewport remains stable without visible camera jitter during movement.

## 3. Reproducibility Contract

1. The session seed is fixed to `20260312`.
2. Map generation is deterministic for that seed.
3. The default FOV radius is `8`.
