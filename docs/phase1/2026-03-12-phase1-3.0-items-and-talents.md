# Phase 1 - 1-3.0 Items & Talents

**阶段**: `1-3.0`  
**优先级**: `P1`  
**前置条件**: `1-2.0` 全部完成  
**对应问题**: 没有物品、装备和天赋，战斗只能停留在单一数值对撞；Phase 1 必须在这一阶段建立最小 build 深度，让“拾取、换装、消耗资源、主动放技能”成为真实决策。

---

## 1. 阶段目标

建立装备系统、属性派生、4 个战士天赋和资源/冷却体系，使玩家开始感知“角色成长”和“战术选择”。

完成标准：

1. 地牢中会生成可拾取物品。
2. 玩家具备背包、装备栏和消耗品使用能力。
3. 装备会影响派生属性。
4. 4 个战士天赋可通过热键使用。
5. `Stamina + 冷却` 机制形成明确约束。

---

## 2. 当前问题

1. 战斗目前只有基础攻击，缺少 build 层差异。
2. 没有装备与消耗品，探索收益不成立。
3. 没有主动技能，玩家决策密度不足。
4. 没有资源约束时，技能系统很容易退化为“无成本按钮”。

### 2.1 本阶段冻结口径

1. 首批只实现 4 个战士天赋：
   - 猛击
   - 冲锋
   - 盾击
   - 战吼
2. 资源类型只做 `Stamina`。
3. 装备类型聚焦：
   - 武器
   - 护甲
   - 消耗品
4. 词缀/材质生成只做 MVP 级组合，不追求完整词库。

---

## 3. 范围与非目标

### 3.1 范围

1. 背包与装备系统
2. 物品生成与 YAML 物品数据
3. 属性派生与装备加成
4. 天赋注册、结算与冷却
5. `Stamina` 资源与回复
6. 背包 UI 与天赋热键 UI

### 3.2 非目标

1. 不在本阶段实现完整天赋树界面。
2. 不在本阶段实现复杂套装系统、稀有掉落表或 crafting。
3. 不在本阶段实现装备耐久、附魔或物品鉴定。

---

## 4. 技术方案

### 4.1 物品与背包

建议文件：

```text
core/src/main/kotlin/com/ktome/core/item/ItemGenerator.kt
core/src/main/kotlin/com/ktome/core/item/InventoryManager.kt
game/src/main/resources/data/items.yaml
game/src/main/kotlin/com/ktome/game/factory/ItemFactory.kt
client/src/main/kotlin/com/ktome/client/screen/InventoryScreen.kt
```

冻结口径：

1. `InventoryManager` 只处理规则，不渲染 UI。
2. 物品定义由 YAML 声明，生成器负责随机组合。
3. 装备/卸下/使用必须可测试，不依赖 UI 事件。

### 4.2 属性派生

建议文件：

```text
core/src/main/kotlin/com/ktome/core/stats/StatsCalculator.kt
core/src/test/kotlin/com/ktome/core/stats/StatsCalculatorTest.kt
```

冻结口径：

1. `STR / DEX / CON / WIL` 的派生公式必须集中在一个地方。
2. 装备修正、天赋加成、基础属性必须分层计算，避免“到处 +1”。

### 4.3 天赋系统

建议文件：

```text
core/src/main/kotlin/com/ktome/core/talent/TalentRegistry.kt
core/src/main/kotlin/com/ktome/core/talent/TalentResolver.kt
core/src/main/kotlin/com/ktome/core/talent/CooldownState.kt
core/src/test/kotlin/com/ktome/core/talent/TalentResolverTest.kt
```

冻结口径：

1. 天赋定义与执行结果必须独立于 UI。
2. 需要目标的天赋必须进入目标选择模式。
3. `Stamina` 不足或冷却中时，天赋请求必须被明确拒绝并给出可解释结果。

### 4.4 UI 壳层

建议文件：

```text
client/src/main/kotlin/com/ktome/client/screen/InventoryScreen.kt
client/src/main/kotlin/com/ktome/client/screen/TalentScreen.kt
client/src/main/kotlin/com/ktome/client/ui/SidebarPanel.kt
```

冻结口径：

1. `InventoryScreen` 只负责展示与输入，不实现背包规则。
2. 热键 `1-4` 与天赋槽位映射固定。
3. 目标选择模式必须可取消、可恢复主地图输入。

## 6. 测试与自证

### 6.1 必测类

1. `ItemGeneratorTest.kt`
2. `InventoryManagerTest.kt`
3. `StatsCalculatorTest.kt`
4. `TalentResolverTest.kt`
5. 建议新增：
   - `StaminaSystemTest.kt`
   - `CooldownSystemTest.kt`
   - `ItemFactoryTest.kt`

### 6.2 必测行为

1. 物品拾取、堆叠、装备、卸下、使用
2. 装备前后属性变化
3. 随机物品生成的基础、材质、词缀组合
4. 4 个天赋的效果、冷却与资源消耗
5. 资源不足/冷却中时的失败分支
6. 消耗品使用后从背包移除

### 6.3 覆盖率门禁

1. `item / talent / stats` 包行覆盖率 `>= 85%`
2. `core` 总体行覆盖率 `>= 75%`

### 6.4 自动化命令

```bash
./gradlew test
./gradlew :core:test --tests "com.ktome.core.item.*"
./gradlew :core:test --tests "com.ktome.core.talent.*"
./gradlew :core:test --tests "com.ktome.core.stats.*"
./gradlew jacocoTestReport
./gradlew :core:jacocoTestCoverageVerification
```

### 6.5 白盒验证

固定白盒验证步骤：

1. 进入地牢后确认地板上出现物品
2. 按 `g` 拾取物品
3. 按 `i` 打开背包并装备武器/护甲
4. 观察属性面板变化
5. 按 `1-4` 施放天赋并确认：
   - 资源被消耗
   - 冷却开始计时
   - 无资源或冷却中时被拒绝
6. 使用药水/卷轴后确认物品从背包移除

## 8. 风险与止损

1. 风险：把装备加成分散到多个系统，后续难以解释数值。  
   止损：所有派生属性统一由 `StatsCalculator` 计算。
2. 风险：天赋逻辑耦合到 UI。  
   止损：UI 只发起请求，结算全部留在 `core`。
3. 风险：随机物品生成不可复现。  
   止损：所有生成测试使用固定 seed。
4. 风险：背包与地牢拾取逻辑混杂。  
   止损：地牢只产生“可拾取事件”，库存规则统一在 `InventoryManager`。
