# Phase 1 - 1-2.0 Combat & AI

**阶段**: `1-2.0`  
**优先级**: `P0`  
**前置条件**: `1-1.0` 全部完成  
**对应问题**: 仅有地图与移动还不能形成真正的 Roguelike 主循环；必须建立回合推进、战斗解析、寻路和怪物行为，玩家才会开始感知“探索有风险、战斗可解释、成长有反馈”。

---

## 1. 阶段目标

把“只有玩家在地图里走动”的切片推进为“怪物存在、会行动、能战斗、可升级”的最小可玩战斗循环。

完成标准：

1. 引入回合调度与能量系统。
2. 玩家与怪物能够进行碰撞式近战。
3. 怪物具备 `chase / kite / patrol` 三类行为。
4. 战斗消息、死亡、经验值与升级链路成立。
5. 新增核心包都有确定性测试与覆盖率门禁。

---

## 2. 当前问题

1. 目前没有“世界如何推进”的统一时序。
2. 没有战斗系统时，地图与 FOV 无法反映风险。
3. 没有路径与 AI，怪物无法形成差异化行为。
4. 没有经验值与升级，战斗就没有长期收益。

### 2.1 本阶段必须冻结的公式与行为

1. 回合调度采用能量制：
   - 每 tick：`energy += speed`
   - `energy >= 100` 获得一次行动机会
2. 战斗首版公式使用 `docs/mvp-development-guide.md` 中定义的 MVP 公式。
3. AI 只实现三类：
   - `chase`
   - `kite`
   - `patrol`
4. Phase 1-2.0 不实现远程弹道系统，远程怪允许先按“保持距离 + 近战替代”或简单射程判断落地。

## 4. 技术方案

### 4.1 回合与世界推进

必须新增独立的 `turn` 包，不允许把回合推进塞进渲染循环。

建议文件：

```text
core/src/main/kotlin/com/ktome/core/turn/TurnScheduler.kt
core/src/test/kotlin/com/ktome/core/turn/TurnSchedulerTest.kt
```

冻结口径：

1. 行动资格只由能量阈值决定。
2. 调度器是纯逻辑，不依赖 libGDX 的 frame time。
3. `client` 只负责把玩家输入封装为行动请求。

### 4.2 战斗解析

建议文件：

```text
core/src/main/kotlin/com/ktome/core/combat/CombatResolver.kt
core/src/main/kotlin/com/ktome/core/combat/DamageResult.kt
core/src/test/kotlin/com/ktome/core/combat/CombatResolverTest.kt
```

冻结口径：

1. 战斗以实体属性和随机数注入为输入。
2. 战斗结果必须显式返回：
   - 是否命中
   - 是否暴击
   - 原始伤害
   - 减伤后伤害
   - 死亡结果
3. 战斗日志通过事件或结果对象传递，不直接写 UI。

### 4.3 路径与 AI

建议文件：

```text
core/src/main/kotlin/com/ktome/core/pathfinding/AStar.kt
core/src/main/kotlin/com/ktome/core/ai/AIDecision.kt
core/src/test/kotlin/com/ktome/core/pathfinding/AStarTest.kt
core/src/test/kotlin/com/ktome/core/ai/AIDecisionTest.kt
```

冻结口径：

1. `AStar` 是纯函数。
2. AI 决策输入必须是完整可测试状态，而不是直接依赖场景对象。
3. `kite` 与 `patrol` 的差异必须能在白盒里稳定复现。

### 4.4 数据加载与怪物工厂

建议文件：

```text
game/src/main/resources/data/monsters.yaml
game/src/main/kotlin/com/ktome/game/data/DataLoader.kt
game/src/main/kotlin/com/ktome/game/factory/EntityFactory.kt
game/src/test/kotlin/com/ktome/game/DataLoaderTest.kt
game/src/test/kotlin/com/ktome/game/EntityFactoryTest.kt
```

冻结口径：

1. YAML 只负责描述，不写行为逻辑。
2. 怪物实体装配逻辑由工厂统一完成。
3. `client` 不直接 new 怪物实体。

### 4.5 升级与日志

建议文件：

```text
core/src/main/kotlin/com/ktome/core/progression/ExperienceSystem.kt
core/src/main/kotlin/com/ktome/core/event/GameEvent.kt
client/src/main/kotlin/com/ktome/client/ui/MessageLog.kt
```

冻结口径：

1. 经验值与升级逻辑留在 `core`。
2. 消息日志只渲染事件，不反向控制规则。

## 6. 测试与自证

### 6.1 必测类

1. `TurnSchedulerTest.kt`
2. `CombatResolverTest.kt`
3. `AStarTest.kt`
4. `AIDecisionTest.kt`
5. `DataLoaderTest.kt`
6. `EntityFactoryTest.kt`
7. 建议新增：
   - `ExperienceSystemTest.kt`
   - `DeathFlowTest.kt`

### 6.2 必测行为

1. 不同 `speed` 实体的行动频率
2. 命中、闪避、暴击、最小伤害下限
3. A* 在可达/不可达场景下的结果
4. `chase / kite / patrol` 的分支行为
5. 怪物 YAML 的完整性与默认值
6. 杀怪获得经验并触发升级

### 6.3 覆盖率门禁

1. `turn / combat / pathfinding / ai` 包行覆盖率 `>= 85%`
2. `core` 总体行覆盖率 `>= 70%`

### 6.4 自动化命令

```bash
./gradlew test
./gradlew :core:test --tests "com.ktome.core.turn.*"
./gradlew :core:test --tests "com.ktome.core.combat.*"
./gradlew :game:test
./gradlew jacocoTestReport
./gradlew :core:jacocoTestCoverageVerification
```

### 6.5 白盒验证

固定白盒验证步骤：

1. 启动可运行 client
2. 新开地图后确认场上出现至少 3 类怪物
3. 观察：
   - `chase` 会接近玩家
   - `kite` 会尽量拉开距离
   - `patrol` 会沿巡逻逻辑移动
4. 与怪物交战并确认：
   - 日志显示命中/伤害
   - 怪物死亡后消失
   - 玩家获得经验
   - 达到阈值后升级

## 7. 出口门禁

1. `./gradlew test` 全绿
2. `./gradlew :core:jacocoTestCoverageVerification` 通过
3. 地牢中存在怪物并可交战
4. 至少 3 种 AI 行为可稳定观察
5. 玩家击杀怪物后可获得经验并自动升级
6. 消息日志能解释战斗结果

---

## 8. 风险与止损

1. 风险：战斗结果直接写 UI，导致无法测试。  
   止损：所有结果先回到 `core` 结果对象或事件层。
2. 风险：AI 依赖渲染/输入状态。  
   止损：AI 只能消费可序列化、可测试的世界快照。
3. 风险：远程怪行为过早复杂化。  
   止损：本阶段只要求行为差异，不要求完整弹道。
4. 风险：升级逻辑分散在多个模块。  
   止损：升级规则统一归拢在 `core/progression`。
