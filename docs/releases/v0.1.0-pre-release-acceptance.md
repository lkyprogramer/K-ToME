# K-ToME v0.1.0 Pre-Release Acceptance

本文件定义 `v0.1.0` 在对外发布前必须完成的最小验收面。

## 1. Direct Conclusion

发布前验收分成两层：

1. 自动化门禁：证明规则、客户端生命周期、覆盖率和打包产物都过线。
2. 桌面白盒：证明真实桌面环境中的交互体验没有偏离自动化 smoke 的假设。

自动化通过，不等于可发布。桌面白盒没有执行，也不能把验收状态标成完成。

## 2. Automated Gate

仓库根目录执行：

```bash
./gradlew preReleaseAcceptance
```

该任务必须同时完成：

1. `clean`
2. `test`
3. `headlessSmoke`
4. `clientSmoke`
5. `jacocoTestReport`
6. `:core:jacocoTestCoverageVerification`
7. `:client:releaseDesktopDist`

自动化证据位置：

1. `build/reports/harness/headless-smoke.json`
2. `build/reports/harness/client-smoke.json`
3. `build/reports/jacoco/jacocoTestReport/html/index.html`
4. `core/build/reports/jacoco/test/html/index.html`
5. `client/build/release/ktome-v0.1.0-desktop.zip`

Nightly 扩展验证：

```bash
./gradlew longRunLab
```

Nightly 证据位置：

1. `build/reports/harness/long-run-summary.json`
2. `build/reports/harness/long-run-summary.md`

## 3. Desktop White-Box Gate

桌面环境中执行：

```bash
./gradlew :client:run
```

必须人工确认：

1. 主菜单可以进入 `New Game` 和 `Continue`。
2. `x` 检视模式能解释玩家、怪物、地面物品。
3. `>` / `<` 上下楼流程与自动化 smoke 一致。
4. `Ctrl+S -> 返回菜单 -> Continue` 可以恢复楼层和背包。
5. 至少完成一条 Victory 路径和一条 Death 路径。
6. 解压 `client/build/release/ktome-v0.1.0-desktop.zip` 后，独立启动一次。

## 5. Known Boundaries

`v0.1.0` 仍然遵守以下边界：

1. 仅桌面版打包。
2. 仅单职业、单 5 层 run。
3. ASCII-first、键盘优先。
4. 自动化 smoke 是发布前证据的一部分，不替代真实桌面白盒。
