# K-ToME 客户端 UI/UX 参考驱动优化改造设计 Review

## 0 · Review 视角与范围

本文对 [`docs/opt/2026-04-20-client-ui-ux-reference-driven-optimization-design.md`](../opt/2026-04-20-client-ui-ux-reference-driven-optimization-design.md) 做深度 review，输入包括：

1. 原设计文档全文。
2. 外部参考站点 [abyss-chronicle.top](https://abyss-chronicle.top/) 的局内截图（日志/战斗/角色/部位/事件一屏态）。
3. 当前仓库截图（`K-ToME v0.1.0`）。
4. 当前客户端源码：`client/src/main/kotlin/com/ktome/client/render/TileRenderer.kt`、`ui/hud/ResourceHud.kt`、`ui/status/StatusHudRenderer.kt`、`ui/status/StatusIconResolver.kt`、`screen/*`。

Review 目标：

1. 确认原文档的方向是否站得住脚。
2. 指出原文档抽象层级偏高、缺失的"像素级"与"微交互级"规范。
3. 扩充只盯一个深渊纪事带来的过拟合风险，引入横向业界参照系。
4. 聚焦用户明确要求的**"哪怕是最细小的改动"**。

Review 不做：

1. 不替代原文档，不重写 phase 合同。
2. 不改 `RenderSnapshot / VisualManifest / iconKey` 单一权威约束。
3. 不讨论具体代码实现细节，实现落地留给后续工作包。

---

## 1 · 结论摘要（TL;DR）

1. **方向正确但抽象层级偏战略**：原文档把"三栏、解释型决策、iconKey 消费"作为骨架是对的；但缺少一层 **Design Token / 微交互 / 可达性** 的像素级规范，直接按现文档实施很容易做出"结构对、感觉错"的界面。
2. **当前代码距离目标缺一整条左栏**：`TileRenderer` 目前是"地图 + 单列 sidebar（340–420px）+ 底部 HUD"的**二栏**结构，没有独立日志栏，没有中栏焦点面板。所谓"三栏不漂移"首先要**把三栏真正立起来**，这是所有后续卡片语言、解释型战斗、telegraph 三位一体的前置。
3. **只盯深渊纪事会过拟合**：原文档"已验证可借鉴点"只列一个参照对象，风险是把一家产品的局部选择当共性。应明确引入 ToME4（本项目词源）、Caves of Qud、Cogmind、Slay the Spire、Darkest Dungeon、Hades II、Balatro、Jupiter Hell、FFXIV 的对比坐标，避免"深渊纪事怎么做我们就怎么做"。
4. **"最细小的改动"完全没被覆盖**：字距、基线、tabular-nums、焦点戒指、伤害飞字生命周期、HP 条呼吸动画、日志叙事块与功能块边界、战斗节拍词高亮、品质色语义化——这些真正决定"手感"的细节文档只字未提。这也是本 Review 重点补强的 §5。
5. **缺可达性与容错态规划**：色盲、高对比度、键盘焦点可见性、空态/错误态/加载态、响应式缩放，原文档 §6.3 只提"图标可回退"，远远不够。

## 2 · 原文档坚持得对的地方

逐条点评，避免"全文点赞"的空话：

1. **§6.1 单一权威**：守住 `RenderSnapshot / VisualManifest / iconKey / log token` 是本项目最有价值的红线，原文档明确写入且在 §12 再次重申禁止在 `client` 复刻规则推导——这条在 Review 中零改动。
2. **§6.3 图标必须可回退**：明确拒绝"纯图标语义"，在 locale 切换与可读性压力下极具克制，属于稀有的"先想清楚再做"。
3. **§6.4 逐层展开**（动作 → 方式 → 目标）：准确提取了深渊纪事最核心的一条——这不是"界面怎么漂亮"，而是"决策复杂度如何分摊"。建议作为战斗、事件、商店、词缀改造的通用骨架。
4. **§7.3 事件房卡片合同**与 **§7.5 背包/商店/检视统一展示语言**：把四个面板拉到同一语法是正确的组件工程学。
5. **§8.4 解释型按钮**把"禁用原因"提升到按钮一等公民：业界大部分独立 roguelike 在这里敷衍，原文档点得很专业。
6. **§10 建议文件落点**标清楚了首页、渲染、状态、契约四块的落盘路径，后续可以直接映射到工作包。

以上方向不动，以下章节逐个补强。

## 3 · 按章节对照的深度批注

### 3.1 §3.2 "已验证可借鉴点"——被忽略的关键信号

截图里至少还有 6 个原文档没提到、但对体验决定性很强的细节：

1. **战斗节拍词的视觉高亮**。深渊纪事把"先手攻击！"这类动词短语单独提亮（橙红+加粗），形成战斗叙事的"节拍器"。K-ToME 当前日志全部同字重同色，缺节奏。
2. **叙事块与功能行的严格分离**。截图底部"『你踏入潮湿的地牢深处……』"用引号+斜体+暗色背景缩进块，和逐行功能日志在视觉语言上是**两套字体节奏**。原文档 §7.2 只说"日志承担三种职责（历史/解释/决策）"，漏掉了第四条：**文学叙事 vs 机制日志**的硬边界。不处理这条边界，"AI 叙事"切换打开后日志会立刻淹没机制行。
3. **回合/位置常驻指示器**。截图中栏顶部的 `F1 | 2/5`、右栏 `T1`、底部"通关 0"是**永不遮挡的进度锚点**，让玩家任何时候都能回答"我在哪、第几回合"。K-ToME 当前这些信息散在标题栏和底部 HUD，且格式是开发态的 `K-ToME v0.1.0 | arrows/numpad move, Enter stairs, x inspect, Ctrl+S save`。
4. **数字层级的复合密度技巧**。部位卡用`36% × 大字号` + `×2 × 小字副标`把"命中率（主）+ 伤害倍率（副）"两条信息叠进一张按钮，且**用字号差而非换行**区分主次。这是原文档 §8.4 "解释型按钮"该但没写的核心技术。
5. **肢体/部位的对称设计**。玩家右栏有"头部/左臂/右臂/躯干/双腿"5 列肢体状态卡，怪物目标卡有"核心/外层/触手"部位条——**同一套视觉语言**。这种对称让"攻击怪物的触手" / "保护自己的双腿"产生物理代入感。原文档 §7.2 "右栏：玩家卡 / 目标卡 / 操作卡"把两者并列但**没强调语言对称**，容易做成玩家一套风格、怪物另一套风格。
6. **右上角"Classic"模式切换**。暗示"同一局可切换渲染风格"（ASCII/Tile/简化），降低入门门槛的同时保留 roguelike 党的 ASCII 情怀。K-ToME 当前有 `UiMode` 但没有"渲染风格切换"这一维度，值得作为远期入口。

### 3.2 §7.1 首页——首屏优先级与差异化

原文档列出了首页四问，但缺：

1. **首焦点规范**。首屏 Enter 应直达"上次存档 / 快速开始"的**单个按钮**，不是选职业。"选职业"是进阶路径，不是首焦点。
2. **新玩家 vs 老玩家的首屏差异化**。首启用"欢迎 + 最小机制速览 + 快速开始"；后续用"最近局面摘要 + 继续 / 新局 / 图鉴进度"。原文档把首页做成一个模板，错失了上下文感知。
3. **底部键位/手柄提示常驻条**（类似《蔚蓝》《Hades》）。K-ToME 目前把键位提示放标题栏，首启玩家根本不会看那里。
4. **Locale 切换位置建议**。放右上角小字切换+当前 locale 标签，**不要藏进设置二级菜单**。多语言用户路径要显性化。
5. **build 能力速览应该是"已解锁 vs 可解锁"**而非"内容清单"。"可玩职业 X / 总 Y"比"可玩职业 X"更有驱动力。

### 3.3 §7.2 左栏日志——从"分类"到"分层+分组+静默"

原文档 §7.2 左栏只说"允许可选前缀图标、关键消息支持分类标题"，远不够。补：

1. **分类轴 × 重要度轴**的二维色彩。当前思路是一维按类别上色，叠上重要度后危险重要行（Boss telegraph）与普通危险行（小怪攻击）视觉权重应**明显不同**，不应都是红。
2. **房间小节锚点**。深渊纪事的 `— 房间 1/5 —`  `— 房间 2/5 —` 水平分隔线让日志具备**空间感**而非仅时间序列。这套锚点必须和 `RenderSnapshot` 的房间切换事件绑定。
3. **同源聚合**。连续三次"雷浆团块触手造成 4 伤害"应聚合为 `×3 −12`；原文档漏了"日志爆量下的信息熵控制"这一关键防线。
4. **静默筛选与折叠**。移动、拾取、被动状态 tick 等低价值行默认折叠成一行"…… 12 步移动、3 次拾取"，点击展开。类似 Cogmind 的 filter 层。
5. **回溯滚动锁**。玩家往上滚看历史时，新日志不打断滚动位置，仅在顶部浮现"↓ 3 条新消息"提示按钮。FFXIV 聊天框标准手法。
6. **叙事块的视觉语言**（见 3.1 第 2 条）：引号 `『』` + 斜体 + 左缩进 8px + 暗色半透明背景 + 与上下机制行之间 4px 空行，**明确不是日志的一行**。

### 3.4 §7.2 中栏——"焦点"与"呼吸"的双重职责

原文档把中栏定义为"世界与焦点面板"，但忽略两点：

1. **留白即呼吸点**。深渊纪事战斗态中栏只有一张居中 ASCII + 怪物名，周围**大面积留白**。这不是浪费空间，而是让眼睛从左右两栏的密集信息中"喘气"。K-ToME 当前把地图填满左半屏，失去了这个焦点呼吸。建议中栏至少保留 30% 纵向留白给"焦点呼吸"，承担"当前叙事锚点"而非"信息输出位"。
2. **焦点锚点与交互状态同步**。中栏在 `MAP` 态是地图焦点，`BATTLE` 态应自动切换到怪物卡面/战斗静态画，不应继续显示地图——否则浪费最贵的屏幕中央位置。原文档 §7.2 列了四个 UiMode，没说**切换的视觉连续性**（是渐隐切换？是推拉？是卡片翻页？）。建议用 200ms fade + 微 scale，保持视觉连续。

### 3.5 §7.2 右栏——对称代入感（肢体 vs 部位）

这是 §3.1 第 5 条的展开：

1. **玩家肢体状态卡必须先于怪物部位卡**出现并**使用同一视觉原语**（图标 + 名称 + 细条 + 数值）。这样玩家第一次进战斗看见"怪物也有部位"时，会自动建立映射："我可以打它的触手，它也能打我的腿"。
2. **玩家卡的"装备槽 + 词缀徽章"双层**。主手⚔️生锈短剑 + 小圆点徽章（+1 / 附魔 / 耐久）。K-ToME 当前右栏用 `武器: 长剑` 纯文本列式，视觉密度和解释力都不足。
3. **资源条层级**。HP 不只是"一条绿条"，应是 "条 + 比例（152/152） + 百分比（100%，HP<50% 自动浮现） + 状态修正"。当 HP<25% 触发 0.8s 呼吸，<10% 持续脉冲——Hades II 的标准处理。
4. **AI 叙事开关位置**。放在右栏侧边（深渊纪事做法）还是顶栏全局？建议 AI 叙事作为**日志区的附加开关**放左栏顶部，因为它影响的是左栏的内容形态；放右栏会让玩家以为它影响的是角色状态。

### 3.6 §7.4 战斗决策——预期区间、克制对比、取消链

原文档 §7.4 分三层写对了，但缺：

1. **预期伤害应给区间而非单值**。`12~18` 比 `15` 更诚实，也符合 `CombatResolutionTrace` 的随机性语义。Slay the Spire 在这一点退化为单值是简化型选择，K-ToME 是模拟型 roguelike，应走 PoE2 区间路线。
2. **克制对比小图标行**。武器对当前目标类型的加成，用 `×1.5 软体` / `×0.6 甲壳` 三四个小图标并列展示，胜过一段文字说明。
3. **取消链规范**。多层决策必须有**统一的返回键位**（ESC 回上一层、Backspace 全返回到根）。原文档没写键位级规范，一旦多个面板各自实现就会出现 ESC 在某些面板直接退出游戏的体验灾难。
4. **禁用态的"显示 vs 隐藏"权衡**。全显但灰（+禁用原因悬停）对新玩家友好但视觉噪音大；只显可执行对老玩家高效但遮蔽 build 可能性。建议默认全显，提供 `仅显示可执行` toggle。

### 3.7 §7.5 背包/商店/检视——品质色与对比框

原文档列了六条展示项，但缺业界已成共识的两个标准：

1. **品质色标准化**。直接采用 ARPG 通用语：common 白、uncommon 绿、rare 蓝、epic 紫、legend 橙、mythic 红。这是 Diablo/PoE/WoW 建立的肌肉记忆，**违反它比遵循它更耗认知**。把品质色作为 Design Token 固化。
2. **对比框**。悬停/聚焦一件"可能穿戴"的装备时，旁边小框显示当前已装备同槽位装备的**差值**（+3 攻击、-1 防御、+腐蚀抗性）。这是 PoE 的 advanced tooltip 标准，K-ToME 背包/检视合同必须预留这个位置，否则后期做加不上。
3. **"NEW"徽章**。最近 30 秒 / 最近一次打开背包未看过的物品打 NEW 小徽章，降低 FOMO——尤其适合 roguelike 短局。

### 3.8 §7.6 状态与 telegraph——倒数、同色、三位一体

原文档说"三个位置可见"是对的，但没说**如何同语言**：

1. **同 icon 同色**。同一 telegraph 在地图 overlay、目标卡徽章、日志前缀必须用完全相同的 `iconKey` 与颜色，不能地图上是红圈、日志上是叹号。
2. **倒数节奏可视化**。T-3 / T-2 / T-1 用数字徽章 + 不同 alpha + 最后一回合脉冲。Slay the Spire 的 intent 是单回合预告，K-ToME 走长预告路线应更接近 FFXIV 的 cast bar。
3. **Boss telegraph 与普通状态视觉权重分离**。原文档点到了但没具体化：建议普通状态图标 20×20px，Boss telegraph 徽章 28×28px + 边框高亮 + 0.6s 呼吸；**不允许共用同一尺寸**。
4. **地图 overlay 警戒形状**。扇形/圆形/线条三种 telegraph 形状应在 `VisualManifest` 明确语义，`client` 消费。否则每个 boss AI 作者会各自发挥。

### 3.9 §8 契约与组件——缺一层 Design Token

原文档 §8 只到"iconKey 消费矩阵、日志渲染模型、目标卡字段、解释型按钮字段"，缺一层**被所有这些组件共享的底层 token**：

1. **颜色 token**：HP/MP/SP/EXP/Gold/品质/状态/危险/好消息/AI 叙事—全部走 token 名，不允许组件内写 `#4ade80`。
2. **间距 token**：栅格 8px；卡片 padding 16px；卡片间距 12px；段间距 24px。
3. **字号/字重 token**：display/title/body/label/caption/numeric 6 档，配套指定 `font-weight` 与 `letter-spacing`。
4. **动效 token**：duration（fast 120 / base 200 / slow 400 / pulse 800）、easing（`ease-out` / `ease-in-out` / `bounce`）。
5. **半径与描边 token**：小 2px、中 4px、大 8px；描边 1px 40% 透明度浅色。

落盘建议 `client/src/main/resources/ui/design-tokens.json`，由 `TileRenderer / StatusHudRenderer / *Hud*` 统一消费。**这条如果不做，§8 所有组件改造都会重新发明颜色和间距。**

## 4 · 业界对比参照系（扩充"只看深渊纪事"的局限）

原文档只列一个参照对象，Review 补十个坐标：

| 参照产品 | 可借鉴的核心点 | 对 K-ToME 的映射 |
| --- | --- | --- |
| **Tales of Maj'Eyal (ToME4)** | tooltip 的"关键词高亮 + 子 tooltip"结构；持续效果条的徽章化 | 本项目词源——动态说明 §7.5 检视页直接照搬 ToME4 tooltip 骨架风险最低 |
| **Caves of Qud** | 单列右栏靠颜色块+分隔符实现视觉分组；纯字符也能做出卡片感 | 当前 K-ToME 最像 Qud，但缺颜色分组——右栏标题色带 + 分隔线即可即时升级 |
| **Cogmind** | 单字符语义密度；filter 层控制日志爆量 | 日志筛选 / 折叠层（见 §3.3 第 4 条） |
| **Slay the Spire** | 敌人 intent 图标（下一招预告） | Boss telegraph 可引入"下一招图标常驻"作为 telegraph 的常态基线 |
| **Darkest Dungeon (1/2)** | 角色卡"头像 + 血条 + 状态行"三联布局；压力/恐惧的徽章化 | 右栏玩家卡结构直接对齐；"肢体状态"可视为 DD 压力系统的变体 |
| **Hades II** | buff 密集但可扫读：图标 + 颜色 + 计数三要素 | 状态图标徽章化标准（§3.8 第 3 条） |
| **Balatro** | 微动效克制精准：数字翻滚、分数飞字、卡牌 hover tilt | 伤害飞字生命周期、数字变化插值节奏（§5.6） |
| **Path of Exile 2** | advanced tooltip 的关键词悬停子 tooltip；装备对比框 | 检视页关键词分层、装备对比框（§3.7 第 2 条） |
| **Jupiter Hell** | 现代化 roguelike 三栏 + 时间轴 + 图标化的完整模板 | K-ToME 目标架构最接近它，直接对齐其三栏比例与时间轴位置 |
| **FFXIV** | 目标指示器（名称 + 血条 + 距离 + 部位 + cast bar）；聊天框滚动锁 | 目标卡数字密度、日志回溯滚动锁（§3.3 第 5 条） |

从表里看出原文档的"解释型决策"结构其实是 **StS intent + ToME4 tooltip + PoE2 对比框 + FFXIV cast bar** 的混合体。明确指认每一点的出处，比笼统说"参考深渊纪事"更有指导性。

## 5 · 最细小的改动清单（用户强调，重点补强）

按"可即时落地"排序。每条都应作为 Design Token 或单点 PR 落地，**不需要等到整体三栏改造**。

### 5.1 字体与数字

1. 全局数字启用 **tabular-nums**（等宽数字），`152/152` 不跳动。
2. 资源条右侧数字格式 `当前/最大`，当前粗（600）、最大细（400）+ 降一档字号。
3. HP 百分比小字叠在条上，默认隐藏，`HP<50%` 自动浮现（fade-in 200ms）。
4. `Lv.` 数字用 small-caps 或轻度加粗；数字比标签大 2-4px。
5. 中英文混排基线对齐：中文字形下沉问题用 `line-height: 1.4` + 中文字号比英文数字大 1px 补偿。

### 5.2 颜色与语义

1. HP 条颜色随比例**渐变**（绿→黄→红），而非离散三色。切点建议 60% 开始黄化，30% 开始红化。
2. 日志色按"类别 × 重要度"二维：类别定色相，重要度定饱和度 + 字重。
3. 品质色统一（common 白 / uncommon 绿 / rare 蓝 / epic 紫 / legend 橙 / mythic 红），品质色**只用于名称**，不污染其他字段。
4. **不依赖纯色传达语义**：危险色必须伴随图标或形状（叹号、三角），色盲模式下仍可读。
5. Danger/Warn/Info/Success 四套语义色 token 化，不允许组件内硬编码色值。

### 5.3 间距与对齐

1. 基线 8px 栅格；卡片 padding 16px；卡片间距 12px；段间距 24px。
2. 数字列右对齐、标签列左对齐；数字与标签之间**空白 ≥ 8px**。
3. 进度条圆角 3-4px，1px 40% 透明度浅色内描边；不要使用无圆角纯色条（视觉硬）。
4. 卡片用"1px 细边 + 4-6% 透明度背景"而非硬背景色，保留暗色氛围。
5. 右栏 sidebar 当前 340–420px，三卡并存时太挤；建议扩到 **380–460px** 并限定最小分辨率 1280 宽。

### 5.4 动效与节奏（克制原则）

1. UI 过场 `120-200ms ease-out`；UiMode 切换 `200ms fade + 微 scale 0.98→1.0`。
2. 状态图标新增 `fade-in 150ms + scale 0.9→1.0`；消失 `fade-out 100ms + scale 1.0→0.95`。
3. HP 条数值变化 `200ms`（掉血）/`400ms`（回血）插值；**回血比掉血慢是肌肉记忆**。
4. 伤害飞字生命周期 `400-600ms`，`ease-out + translateY(-20px) + fade-out`。
5. Telegraph 倒数：T-3/T-2/T-1 用 alpha `0.5/0.7/1.0` + 最后回合 `0.6s` 脉冲。
6. 日志新条目 `slide-in 200ms + 一次性高亮 800ms`。
7. **禁止** UI 元素常驻动画（背景流光、边框呼吸全局开），只允许关键风险项呼吸。

### 5.5 焦点与可达性

1. 所有可聚焦元素加 **2px 焦点戒指**（外描 + 2px offset），与 hover 态视觉明确区分。
2. 禁用态 `opacity 0.45 + cursor: not-allowed + tooltip（禁用原因）`。
3. 键盘 Tab 链：上栏 → 中栏 → 右栏 → 底部 HUD；Shift+Tab 反向。
4. 最小字号 body 12px、label 10px；提供"高对比度模式"（所有透明度 ×1.4、字重 +100）。
5. 色盲模式：红绿色盲版本用橙/蓝替代，Design Token 提供语义映射表。

### 5.6 战斗节拍词与伤害飞字

1. "先手攻击！" "暴击！" "破甲！" "闪避！"用**色彩 + 字重 + 0.3s scale pop 动效**突出。
2. 多次同源伤害聚合 `×3 −12` 显示，避免日志爆量。
3. 单次大伤害（>20% HP）在伤害飞字旁加"！"后缀且放大 1.3×。
4. 治愈飞字用**上浮速度减半**（`800ms`），与伤害节奏区分。
5. 状态施加飞字（`+灼烧` `+眩晕`）出现在目标卡图标旁，**不进日志主列**。

### 5.7 日志微结构

1. 叙事块（AI 叙事）：`『』` + 斜体 + 左缩进 8px + 4% 暗色背景 + 上下各 4px 外距，**视觉明确不是一行日志**。
2. 系统块：子标题 `【xxx 系统】` + 子项 `·` + 整体缩进 8px，仅用于入门引导与重大规则变化，不污染常态日志。
3. 房间锚点：`— 房间 N/M —` 水平分隔线 + 对比度 2:1 浅色；点击可折叠该房间内所有日志。
4. 日志等级筛选 toggle：`全部 / 仅重要 / 仅战斗 / 仅奖励`；默认"全部"，老玩家可切"仅重要"。
5. 回溯滚动锁：向上滚动超过 2 屏时顶部浮现"↓ N 条新消息"按钮，点击返回底部。

### 5.8 目标卡与部位卡细节

1. 怪物类型用**圆角小徽章**（软体/甲壳/飞行/亡灵）放名字旁，用 `iconKey` 驱动。
2. 部位卡：`进度条 + 当前/最大 + 百分比 + 克制倍率（×2 / ×0.6）` 四要素；命中率大字、倍率小字副标（见 §3.1 第 4 条）。
3. 当前选中部位背景**色带呼吸 1.2s**；其他部位 `opacity 0.75`。
4. 部位被击破时 `crack 动画 300ms + 红色闪烁` + 日志锚点"☠ 核心破碎"。
5. 玩家肢体状态卡与怪物部位卡共享"细条 + 图标 + 百分比"骨架，但玩家卡多一条**持续效果徽章行**（流血/骨折/中毒…）。

### 5.9 顶栏与键位提示

1. 当前标题栏 `K-ToME v0.1.0 | arrows/numpad move, Enter stairs, x inspect, Ctrl+S save` 是**开发态残留**。建议改为：
   - 左：`K-ToME · 无名勇士 · 战士`（品牌 + 角色）
   - 中：`回合 T1 · 层 F1 · 房间 2/5 · 通关 0`（永不遮挡的进度锚点）
   - 右：`EN / 中  ⏸  ☰`（locale 切换 / 暂停 / 菜单）
2. 键位提示应**底栏常驻**并根据 UiMode 动态变化，不再挤标题栏。
3. 顶栏对比度 1.2:1（淡，不抢焦点）；玩家可手动折叠以释放纵向空间。

## 6 · 当前代码缺口复核

对照 §7 三栏目标，当前 `TileRenderer` 实际状态：

| 目标 | 当前状态 | 缺口 |
| --- | --- | --- |

| 解释型按钮 | 暂无 Button 基座 | 需抽 `ExplainedButton(icon, title, subtitle, cost, risk, disabledReason)` 基座 |

## 8 · 可量化验收（补强 §11.2）

原文档 §11.2 描述性验收不可度量，建议升级：

1. **首屏任务时间**：冷启动 → 进入战斗的首次按键路径，中位数 ≤ 8 秒，P95 ≤ 15 秒（小样本 5 人测试即可）。
2. **三栏面积比**：日志 / 焦点 / 状态纵向面积比 1 : 1.2 : 1 ± 0.1；分隔线对比度 ≥ 3 : 1。
3. **目标识别正确率**：新玩家在目标卡出现后 3.5-4.5 秒内，能正确回答"最弱部位 + 最克制动作"，错误率 < 15%。
4. **卡片骨架一致性**：背包 / 检视 / 商店 / 事件四面板，字段差异 ≤ 5 项（标题 / 描述 / 效果 / 动作 / 禁用）。
5. **Telegraph 响应**：Boss telegraph 出现后 0.3 秒内，眼动热区命中率 > 80%（可用简化版"玩家事后自述在何时注意到"代替）。
6. **日志爆量阈值**：连续 20 回合战斗，日志可见行数 ≤ 40 行（聚合生效）；未聚合版本会到 ~120 行。
7. **locale 切换回归**：`zh-CN ↔ en-US` 切换后所有按钮副标题、禁用原因、风险说明无裸字符串回退（`locale-lint` 自动化）。
8. **色盲模式**：Deuteranopia 模拟下所有危险/好消息仍可区分（图标 + 形状双保险）。

## 9 · 风险补强

补原文档 §12 未覆盖的风险：

1. **Design Token 与 RenderSnapshot 的边界**。Design Token 是 `client` 表现层私有物，**不允许**进入 `RenderSnapshot` 或 `VisualManifest`，否则会出现"规则层依赖颜色"这类反向污染。Token 与 manifest 的分工必须明确写入约束。
2. **动效预算与性能**。所有微动效总预算 ≤ 每帧 1ms；不允许出现常驻动画导致电池 / 发热异常。需要一个"动效预算"断言进入 `ClientSmokeHarnessTest`。
3. **肢体/部位对称是否破坏单一权威**。玩家肢体状态是否已在规则层存在？如果没有，`client` **不得**自造一套肢体 HP；必须先在 `game/core` 立法，再由 `client` 消费。这条是本 Review 最大的隐藏风险点，实施 §3.5 前必须对齐。
4. **"Classic 模式切换"的蔓延**。渲染风格切换（ASCII / Tile / Simplified）若作为正式入口，会让 golden screenshot 数量 ×3，且风格间的 a11y 一致性很难保证。**不建议**在 `P2-W5 ~ P3-W4` 范围内开口，作为 Phase 5 之后的长期选项更稳。
5. **"引入业界参考坐标"不等于引入业界美术风格**。对比表里的 Hades II / Balatro 都有强烈美术风格，K-ToME 必须明确：借鉴的是**信息架构与微交互**，而非美术。这条也要写入禁止事项。

## 10 · 结语

原设计文档的方向、边界、禁令都稳，是一份优秀的"战略层"文档。本 Review 做的事是把它从"战略"拉到"像素"：

1. 补**三栏结构性改造**作为 P2-W5.0 前置，否则所有后续组件工作会踩在二栏 sidebar 上反复迁移。
2. 补**Design Token** 文件作为颜色 / 间距 / 字号 / 动效的单一权威，让 §8 的组件改造有共同地基。
3. 补**业界坐标**，用 ToME4 / CoQ / StS / DD / Hades II / PoE2 / Jupiter Hell / FFXIV 给每条建议找实锤出处，避免"深渊纪事过拟合"。
4. 补**"最细小"的改动**清单（§5），把 tabular-nums、焦点戒指、伤害飞字、战斗节拍词、叙事块边界这类决定手感的细节显性化。
5. 补**可达性、容错态、量化验收**，让"体验"可以被断言而非描述。

如果只能选一件最先做的事：**把三栏立起来，并建立 Design Token 文件**。其他所有改动都依赖这两块地基。

## 11 · 深渊纪事的结构是否适用于 K-ToME

结论先说：**部分适用，不能照搬**。原文档把深渊纪事当作"体验模板"引用，但它与 K-ToME 的**介质、主交互通道、叙事密度、节奏模型、视觉原语**都不同。不区分这些差异而按栏位照搬，会把 Web 产品的局部决策误当作共性。

### 11.1 技术与介质差异

| 维度 | 深渊纪事 | K-ToME |
| --- | --- | --- |
| 运行环境 | Web / SPA / shadcn/ui | libgdx 桌面 + Kotlin / 本地窗口 |
| 渲染模型 | DOM + CSS（回流/合成） | 逐帧 GPU 绘制（TileRenderer canvas） |
| 主输入通道 | 鼠标为主 + 触屏 | 键盘为主 + 数字键位热键 |
| 动效机制 | CSS transition / tween 引擎多层 | 需手写 interpolation，帧预算敏感 |
| 视窗模型 | 可无限纵向滚动，可缩放 | 固定或有限缩放，字符栅格敏感 |
| 切屏成本 | 页面路由几乎免费 | Scene 切换需保持 RenderSnapshot 连续 |
| 叙事密度 | 文本驱动（每屏一事件） | 规则驱动（每回合多事件） |

这七条差异意味着深渊纪事的下列做法**直接搬过来会失真**：

1. **三栏并列常驻**。Web 浏览器窗口通常 ≥1440 宽；桌面 roguelike 很多玩家用 1280×800。三栏并列会把每栏压到 <400px，部位卡和按钮副标题都会爆行。K-ToME 的更优形态可能是"**中央地图 + 左右可折叠抽屉**"：默认展开三栏，玩家可按 `Tab` 收起右栏让地图回到全屏，这是深渊纪事不需要考虑但 K-ToME 必须给的自由度。
2. **背包/商店/检视作为"sidebar 内页切换"**。Web 用路由切页几乎免费；K-ToME 的 sidebar 只有 400px，切页等于在很窄的竖条里塞所有内容，阅读节奏差。**更适合 K-ToME 的是"模态抽屉"**：按 `i` 打开背包，用半透明遮罩 + 中央居中面板（~800×600）呈现，带网格物品 + 右侧详情 + 底部动作——类似 ToME4 / CoQ 的背包窗口。这也避免在战斗态意外点开背包破坏当前决策上下文。
3. **叙事优先于机制**。深渊纪事 AI 叙事是主体验；K-ToME 是规则驱动 roguelike，AI 叙事必须默认**弱化**，作为机制日志之上的一层可选"剧本"，不应像深渊纪事那样占用主视觉权重。
4. **"分享"按钮**。Web 有天然的社交链接 + 图片导出能力；K-ToME 是本地桌面程序，更合理的是**截图快捷键 + 保存 seed 到剪贴板**，放到选项菜单而非主界面。
5. **鼠标 hover 驱动的 tooltip 链**。K-ToME 是键盘优先，**hover 不是一等公民**。tooltip 应由"**检视光标（x 键）+ 键盘聚焦环**"驱动，配合 `?` 键打开当前聚焦项的详情。
6. **CSS 动效的"随时呼吸"风格**。CSS 下常驻动画成本低；GPU 逐帧下每条常驻动画都吃预算。K-ToME 的动效必须**回合锚定**——每回合边界播一次，而不是持续流动。

### 11.2 深渊纪事真正值得抽象出的原则

把深渊纪事从"一个 Web 产品"抽象成"可跨介质复用的原则"后，留给 K-ToME 的是：

1. **解释型决策分层**（动作 → 方式 → 目标 → 预期）：这是**认知心理学**层面的信息架构，和 Web/桌面无关，值 100% 借鉴。
2. **对称代入感**（玩家肢体 ↔ 怪物部位共享视觉语言）：和介质无关，值 100% 借鉴。
3. **iconKey 全链路消费**：和介质无关，值 100% 借鉴。
4. **日志的分层责任**（历史/解释/决策 + 本 Review 补的叙事块边界）：和介质无关，值 100% 借鉴。
5. **禁用原因作为按钮一等公民**：和介质无关，值 100% 借鉴。

至于**三栏并列、sidebar 切页、鼠标 hover 链、CSS 常驻动画、分享按钮**这些——**不借鉴，用桌面介质的原生最优解替代**。

## 12 · K-ToME 相对 Web 参考的独特机会（怎样做得更好）

深渊纪事受限于 Web，而 K-ToME 是桌面 + GPU 渲染 + 回合制规则 + Tile 地图，有**五个深渊纪事做不到**的体验升维点。这是"比深渊纪事更好"的真正方向。

### 12.1 空间即 UI（Diegetic HUD）

Tile 渲染的最大优势是**信息可以直接落在地图里**，不必全走 sidebar。业界样板：CoQ、Jupiter Hell、Into the Breach。

1. **Telegraph 直接画在地图格**：Boss 下一招的扇形/直线/范围用半透明红色格子叠加，配合回合倒数数字徽章——比放在"目标卡 + 日志 + overlay 三处"更直观，因为 telegraph 本来就是**空间信息**。
2. **状态图标头顶徽章**：怪物头顶浮空图标行（流血 / 眩晕 / 充能 / 护盾），0.5s 淡入淡出，避免全都挤到右栏状态行。
3. **伤害/治疗飞字直接从 tile 浮起**：击中位置正上方浮起 `-12`，400ms 上浮 + 淡出；暴击放大 1.3×；治疗绿字下浮——比在日志里找一行效率高十倍。
4. **可交互 tile 微光**：祭坛、宝箱、商人、隐藏房入口用 0.8s 节奏的 1px 亮边呼吸，暗示"这里可互动"。CoQ 的 `look` 模式是文字提示，K-ToME 可以做视觉提示，**降低键盘检视的门槛**。
5. **路径预览线**：`Shift + 方向键`显示从当前位置到目标的最短路径虚线（A* 已有），避免玩家盯着网格心算。

这五条 Web 版深渊纪事因为没有 Tile 地图做不到，是 K-ToME **结构性优势**。

### 12.2 回合即节奏器（Turn-Paced Animation Bus）

回合制给动效一个天然的"小节线"。每回合边界是一次 tick，所有动效对齐到这个 tick，比 Web 的实时动效更有章法、更省预算。

1. **统一动效调度器**：所有 UI 动效只在回合推进/回合结束/模态切换这三种时刻触发，**不允许常驻动画**（HP<10% 呼吸除外）。可以定义 `TurnBoundaryAnimator`，所有组件订阅它。
2. **回合指示器作为"心跳"**：右上角 `T12` 回合数字在每回合推进时闪一次（120ms），建立"节拍感"。
3. **AI 行动阶段可视化**：敌方回合时屏幕顶部浮现 `敌方行动中 · 1/3 雷浆团块`进度条，每个敌人行动之间留 80-150ms 停顿，让玩家跟得上战斗节奏——比深渊纪事"瞬间结算一屏文字"更有沉浸感。

### 12.3 键盘优先的"按键即 UI"

K-ToME 是键盘驱动，**按键应该在界面上显性可见**——这是深渊纪事（鼠标驱动）不需要做的。

1. **可用按键 badge**：所有当前可执行动作按钮左上角显示其热键（`1` `2` `3` `4` `A` `D`...），不靠底部键位表。
2. **当前回合可用键高亮**：耐力不够时 `猛击 8 耐` 键位 badge 变灰 + 禁用原因 tooltip；刚好够时呼吸高亮。
3. **按键 heatmap 模式**：按住 `?` 键时，屏幕上所有当前可按的按键浮起高亮（类似 CAD 软件的 Alt 菜单提示）。新玩家学习期用，老玩家不会注意。
4. **双热键系统**：数字键快捷 + 首字母助记（`A`ttack / `D`efend / `S`kill / `I`nventory），玩家两种习惯都能满足。ToME4 做得好但不够一致，K-ToME 可以一次性做对。

### 12.4 模态抽屉 + 焦点锁

桌面桌面 + GPU 下模态窗口比 Web 的路由切页有额外优势：**焦点锁定**和**背景虚化**。

1. **模态背包/商店/检视**不是 sidebar 切页，而是居中 ~800×600 窗口 + 背景地图虚化 (`blur 4px + brightness 0.6`)。GPU 虚化成本低，Web 做不到这么顺滑。
2. **焦点锁定**：模态打开时键盘输入只作用于模态，地图态键位不响应；关闭时自动回到上次光标位置。深渊纪事 Web 路由切页后很容易丢 scroll 位置，桌面模态不会。
3. **模态内分屏**：背包模态 = 左 60% 网格物品 + 右 40% 详情 + 底部动作栏。详情栏在 hover（鼠标）或光标停留（键盘）0.3s 后显示——这种分屏结构 sidebar 放不下。

### 12.5 Seed + 快照的"可分享"维度

深渊纪事的"分享"是社交链接；K-ToME 是本地 roguelike，可分享的维度反而更丰富：

1. **局面截图包含 seed / 回合 / 当前状态**：`F12` 截图时自动把 seed、turn、playerBuild、最近 10 条日志拼在图片右下角元信息区（可关）。玩家发到社群别人可以"Play this seed"。
2. **死亡回放**：最后 20 回合的 `RenderSnapshot` 序列保留，死亡后允许逐帧回放。深渊纪事没做（Web 内存成本高），K-ToME 桌面内存宽裕完全可以做。
3. **构筑片段分享**：把当前 build（职业 + 关键词条 + 装备）序列化为短文本 `K-ToME:v0.1:warrior:iron-will+phase-gate:longsword/shield`，玩家可以拷贝到社群讨论。PoE 的"构筑码"常见做法。

### 12.6 小结：定位差异的设计哲学

深渊纪事的设计哲学是 **"把 roguelike 翻译成 Web 小说的阅读节奏"**——每屏一事件、文字驱动、鼠标点按。

K-ToME 应该明确自己的设计哲学是 **"把 roguelike 的空间规则感放回玩家指尖"**——地图主导、键盘驱动、回合节拍、diegetic HUD。

抓住这个差异，就不会陷入"三栏不像深渊纪事"或"AI 叙事没它好看"的伪焦虑。**K-ToME 要做的是业界桌面 roguelike 的最优解，而不是某个 Web 产品的像素级复刻。**
