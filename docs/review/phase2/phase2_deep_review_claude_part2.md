# Phase2 深度审查报告 — Part 2：当前阶段玩法体验总评

---

## 4. 当前阶段玩法体验总评

### 4.1 核心循环（Core Loop）分析

#### 4.1.1 当前循环形态

```
进入地图 → 探索房间 → 遭遇怪物 → 回合制战斗 → 怪物死亡(仅获 XP) → 升级(获得 stat/talent points) → 继续探索 → 下楼梯 → Boss → 胜利/死亡
```

#### 4.1.2 致命断裂：战斗 → 奖励环节

**这是当前 Phase 2 最严重的体验问题，没有之一。**

当前实现中，杀死怪物只会获得经验值（`ExperienceSystem.applyReward`），不会产生任何物品掉落。loot profile 数据（`loot/index.yaml`）已经定义了 common/elite/boss 三档掉落表，包含完整的物品列表，但 `FoundationGameSession` 中怪物死亡流程没有调用 `ItemGenerator` 或查询 loot profile。

**证据链**：
- `loot/index.yaml`：定义了 `loot.foundation.common`（healing_potion, short_sword 等）、`loot.foundation.elite`（chain_mail, mana_potion 等）、`loot.foundation.boss`（battle_axe, plate_armor 等）
- `ItemGenerator.kt`：完整的随机物品生成器，支持品质（COMMON/MAGIC/RARE）、材料、词缀
- `FoundationGameSession.kt`：怪物死亡仅执行 XP 奖励，没有掉落逻辑

**体验后果**：
1. 战斗变成纯消耗行为——每次战斗消耗 HP/资源，但除了 XP 没有任何回报
2. 玩家没有"多打一场就可能获得更好装备"的驱动力
3. 整个物品系统（24 件物品 + 4 材料 + 7 词缀）实质上处于休眠状态，只有起始装备能被体验到
4. ItemGenerator 的品质/材料/词缀机制——本应是最有 Roguelike 特色的随机乐趣——完全不参与游戏流
5. **这不是"缺内容"，而是核心循环的断裂**。等于一个 ARPG 所有怪都不掉装备

**为什么是 Phase 2 必须修的**：不修这个问题，Phase 2 所有其他系统（物品品质、材料、词缀、loot profile 分层、zone reward）全部无法被玩家触及。这不是"后续补充内容"能解决的，而是核心循环不成立。

#### 4.1.3 次级断裂：单 zone 循环

即使在 P2-B 切片中，玩家只能体验 `shattered_outpost` 的 2 层，然后直接面对 Bandit Captain boss。route transition 尚未实现（`FoundationGameConfig.zoneRoute` 默认只含单个 zone）。

这意味着当前的"短局"实际上是一个约 10~15 分钟的单 zone 清扫，而非设计文档预期的 30~60 分钟四 zone 路线。

#### 4.1.4 循环评级

| 环节 | 当前状态 | 评分（1~5） |
|------|---------|------------|
| 进入地图 / 探索 | BSP 地图生成 + FOV shadowcasting，探索感基本存在 | 3.5 |
| 遭遇战斗 | 回合制 + 速度调度，基础框架扎实 | 3.0 |
| 获取奖励 | **仅 XP，无物品掉落** | **0.5** |
| 角色成长 | 升级有 stat/talent points 但 statGrowth 未生效 + 天赋全开 | 1.5 |
| 解锁新选择 | 无——1 级已拿满工具箱 | **0.5** |
| 驱动下一局 | 当前无"再来一局"的理由 | 1.0 |

**总评：核心循环严重残缺，处于"技术上可运转但体验上不成立"的状态。**

### 4.2 战斗体验

#### 4.2.1 战斗机制基础

战斗系统的底层实现质量不错：
- 命中率公式：`0.85 + (accuracy - evasion) * 0.01`，clamp 到 `[0.05, 0.95]`
- 暴击率：`0.05 + dex * 0.002`，clamp 到 `[0, 0.50]`
- 物理减伤：`max(0, rawDamage - targetDefense)`
- 元素抗性：`finalDamage * (1.0 - resistance/100)`
- 速度调度：能量累积制（threshold 100），支持同时行动

这套公式简洁且具有可调性，是一个好的起点。

#### 4.2.2 关键问题：战斗决策缺乏深度

**问题 1：DamageType 六通道形同虚设**

`DamageType.kt` 定义了 PHYSICAL/FIRE/COLD/LIGHTNING/HOLY/SHADOW 六种伤害类型，CombatResolver 也实现了元素抗性计算。但由于所有怪物默认 0 resistance，没有任何一个 monster 在 YAML 中配置了 `resistances` 字段，所有伤害类型在实战中完全等价。

```
# 所有 24 个 monster 的 YAML 结构相同：没有 resistances 字段
# 意味着 CombatResolver L47 的 targetResistance 永远为 0
```

**体验后果**：
- Arcanist 的 fireball (FIRE) 和 ice_bolt (COLD) 除了伤害倍率不同，没有战术区别
- HOLY +50% 对亡灵的特殊设计只存在于文档，Templar 没有对亡灵的类型优势
- 玩家不需要考虑敌人弱点/抗性来选择技能，战斗退化为"谁伤害倍率高用谁"
- 这不是"以后加内容"能解决的——如果 Phase 2 不验证 DamageType 差异化的基本体验，Phase 3 的抗性递减公式就建在没有反馈的地基上

**问题 2：AI 行为高度同质**

当前 AI 只有三种行为：CHASE（追击）、KITE（放风筝）、PATROL（巡逻）。所有怪物的 `aiProfileId` 在 `ai/index.yaml` 中定义，但实际行为差异非常小：
- CHASE：直线追，进入范围就打
- KITE：保持距离，远程攻击
- PATROL：固定路线巡逻

没有：使用技能的 AI、走位/包抄策略、对玩家状态的反应、精英/Boss 的相位行为、召唤/逃跑/治疗等策略行为。

**体验后果**：
- 所有近战怪感觉一样，只是 HP 和伤害不同
- 精英与普通怪的区别只有数值更高，没有行为差异
- Boss（bandit_captain, cultist.dungeon_lord）也只是 HP 更高的 CHASE 怪

**问题 3：缺少 AOE 与位置策略反馈**

虽然天赋系统支持 AOE（如 sweeping_strike, frost_nova, war_cry），BSP 地图也生成了走廊和房间，但当前缺少：
- 怪物 AOE 或范围攻击（所有怪物只有基础近战/远程普攻）
- 地形交互（没有可破坏地形、没有视线遮挡利用、没有逃生策略）
- 位置有意义的遭遇设计（怪物随机分布，没有伏击、夹击、据点等编排）

#### 4.2.3 亮点

- 天赋系统本身的设计质量很高：32 个天赋全部有独特的 resolution 逻辑，包括击退、眩晕、碎甲、闪避移动（blink/roll/shadowstep/charge）、自身 buff、范围 debuff、治疗、资源恢复
- 资源系统的四种不同回复策略（PerTurn/OnHit/OnDamageTaken/Composite）确实为不同职业创造了不同的战斗节奏潜力
- 冷却时间 + 资源消耗的双重约束为技能选择创造了最基础的决策空间

#### 4.2.4 战斗评级

| 维度 | 当前状态 | 评分 |
|------|---------|------|
| 基础机制扎实度 | 命中/暴击/减伤公式完整且可调 | 4.0 |
| 决策有意义性 | 低——无抗性差异、无 AI 策略、无位置压力 | 1.5 |
| 职业差异感 | Vanguard/Arcanist 有基础差异（近战/远程），Rogue/Templar 未验证 | 2.0 |
| 节奏与爆发感 | 天赋冷却创造了基本节奏，但缺少视觉/音频反馈放大 | 2.0 |
| 战斗-判断-反馈循环 | 弱——杀敌只有 XP，无掉落"叮"的正反馈 | 1.0 |

### 4.3 成长与构筑

#### 4.3.1 经验与升级系统

`ExperienceSystem.nextLevelExp = level * 100 + 50`

- Level 1→2：需要 150 XP
- Level 5→6：需要 550 XP
- Level 10→11：需要 1050 XP
- 每级 +2 stat points
- 每 2 级 +1 talent point（奇数等级时）
- 升级回满 HP 和 Stamina

这是一个合理的线性增长曲线。但存在以下问题：

#### 4.3.2 关键问题：成长感虚假

**问题 1：statGrowth 未生效**

profession schema 中定义了 `statGrowth`（例如 Vanguard str+2/dex+1/con+2/wil+0），但 `ExperienceSystem.applyReward` 只分配 unspentStatPoints，不自动叠加 statGrowth。玩家升级后只获得可分配的点数，但职业本身不会随等级产生差异化的属性增长。

**体验后果**：
- 等级 1 的 Vanguard 和等级 10 的 Vanguard 的差异只来自于手动分配的 stat points
- 没有"Vanguard 越高级越坦"的自然成长感
- 不同职业的成长曲线完全相同（都是 2 点/级自由分配）

**问题 2：天赋全开问题**

每个职业的 `startingTalents` 直接列出 4 个技能，包括设计上应该是后期才解锁的技能。例如：
- Vanguard `startingTalents`: power_strike, shield_bash, guard_stance, war_cry
  - war_cry 的 unlockLevel 是 1，但它是 Warcry 树的核心技能
  - 加上 unyielding (unlockLevel 5) 虽然不在 startingTalents 中，但...
- 更关键的是 `TalentProgression.unlockedTalentIds` 的逻辑：它先把 startingTalents 加入（只要 level >= unlockLevel），然后扫描所有 tree nodes 把 level 足够的全部加入

这意味着到了 level 4~5，玩家已经解锁了绝大部分天赋。以 Vanguard 为例：
- Level 1: power_strike(1), shield_bash(1), guard_stance(1), war_cry(1) = 4 技能
- Level 2: +sweeping_strike(2) = 5 技能
- Level 3: +charge(3) = 6 技能
- Level 4: +sunder_armor(4), +intimidation(4) = 8 技能
- Level 5: +unyielding(5) = 9 技能（含 charge 共 9 个，8+charge）

**到 level 5 时，Vanguard 的全部 9 个天赋（8 个正式 + 1 个 charge）已经全部解锁。** 之后的升级只能提升天赋等级（通过 talent points），不再有新技能解锁。

**体验后果**：
- "我升级了会有什么新技能？"这个最基础的 RPG 驱动力在 level 5 就完全消失
- 玩家从 level 5 到 level 20 的 15 个等级里没有任何新解锁
- 构筑选择变成纯数值加点（给 power_strike 加 1 级 vs 给 shield_bash 加 1 级），没有"这局走火系还是冰系"的路径选择
- 对比 ToME：ToME 在 level 50 的天赋树里仍有大量未解锁内容，每次升级都有"我要点什么"的决策快感

**问题 3：构筑空间被压扁**

当前每个职业只有 3 棵天赋树、8~9 个天赋。且 talent point 获取速度（每 2 级 1 点）意味着到 level 10 时只有约 5 个 talent points 可分配——但这时所有技能已经解锁。

问题不在于天赋数量不够（Phase 2 的 8 个/职业是合理的阶段目标），而在于：
- 没有分支选择——不是"火系 OR 冰系"，而是"火系 AND 冰系全都要"
- 没有资源约束导致的选择取舍——talent points 足够把全部技能升到 2~3 级
- 没有装备联动的构筑分化——物品不影响天赋效果或解锁方向

#### 4.3.3 成长评级

| 维度 | 当前状态 | 评分 |
|------|---------|------|
| 升级体验爽感 | 有回满 HP 的正反馈，但其他收益不明显 | 2.0 |
| 成长改变玩法 | 不改变——level 5 和 level 1 玩法一样，只是数值更高 | 1.0 |
| 构筑分化 | 无分支选择，所有同职业玩家最终 build 完全相同 | 0.5 |
| "这局试另一种 build"的驱动力 | 不存在——没有 build diversity | 0.5 |
| 跨职业重玩驱动 | 4 职业资源机制不同有基础差异，但天赋数量太少且全解锁 | 2.0 |

### 4.4 奖励驱动与掉落体验

#### 4.4.1 当前奖励来源

| 奖励来源 | 是否存在 | 内容 |
|----------|---------|------|
| 杀怪 XP | 是 | 经验值 |
| 杀怪掉落 | **否** | loot profile 数据存在但未接入 |
| Boss 掉落 | **否** | boss loot profile 存在但未接入 |
| 宝箱/交互物奖励 | 部分 | supply_crate 存在但奖励机制不明确 |
| 商店 | 否 | Phase 2 无商店 |
| 任务奖励 | 否 | objective 存在但没有明确物品奖励 |
| Zone 通关奖励 | 否 | route 未实现 |

#### 4.4.2 根本问题：奖励系统几乎不存在

这是一个 Roguelike 游戏。Roguelike 的核心乐趣之一是"每次探索都可能发现改变局势的物品"。但当前：
- 杀怪不掉东西
- 没有随机宝箱
- 没有商店/交易
- 没有任务奖励物品
- Boss 杀了也不掉东西

玩家获取装备的唯一途径是起始套装。整个游戏过程中，装备不会变化。

**这比"奖励不够丰富"严重得多——这是"奖励系统不存在"。**

#### 4.4.3 被浪费的高质量物品系统

讽刺的是，代码层面的物品系统质量很高：
- `ItemGenerator` 支持随机品质（COMMON 60%→MAGIC 30%→RARE 10%，按楼层动态调整）
- 材料系统（IRON→STEEL→MITHRIL→ADAMANTITE）按楼层阶梯解锁
- 词缀系统（3 前缀 + 4 后缀）叠加属性修正
- 24 件基础物品覆盖武器/防具/饰品/消耗品全品类
- loot profile 按 common/elite/boss 分三档

这是一个设计得很好的物品生成管线，但它从未被战斗循环调用。等于造了一辆跑车但没有加油。

#### 4.4.4 奖励评级

| 维度 | 当前状态 | 评分 |
|------|---------|------|
| 奖励频率 | **几乎为零**——只有 XP | 0.5 |
| 奖励层次 | 不存在——没有 common/elite/boss 掉落分层体验 | 0 |
| 奖励影响决策 | 不存在——装备不变化 | 0 |
| 掉落记忆点 | 不存在 | 0 |
| "每次战斗都有价值" | 否——战斗是纯消耗 | 0.5 |

### 4.5 探索与重复游玩价值

#### 4.5.1 地图生成

BSP 地图生成器（`BspGenerator.kt`）能产生足够多样的房间/走廊布局，配合 FOV shadowcasting，探索的基本"发现感"是存在的。

#### 4.5.2 关键问题

**问题 1：Zone 视觉/体验单一**

当前只有一个可玩 zone（shattered_outpost），2 层地图。即使 4 zone 的 YAML 数据已经定义了不同的怪物池和 tileset key，但 route transition 未实现，玩家无法实际体验到环境变化。

**问题 2：没有随机事件/发现**

当前地图上只有：墙壁、地板、怪物、楼梯、交互物。没有：
- 随机宝箱
- 隐藏房间
- 特殊事件
- 陷阱
- NPC
- 随机祭坛/泉水

探索过程是"走过所有房间，杀掉所有怪，找到楼梯"，高度线性。

**问题 3：重玩变化有限**

BSP 生成的房间布局会变化，但由于奖励系统缺失、构筑路径单一、zone 只有一个，重玩体验高度重复。当前的"再来一局"动力几乎不存在。

#### 4.5.3 探索评级

| 维度 | 当前状态 | 评分 |
|------|---------|------|
| 地图多样性 | BSP 提供基础变化，但单一 zone 限制了环境多样性 | 2.5 |
| 未知感/风险感 | FOV 提供基础未知感，但缺少危险事件和惊喜 | 2.0 |
| 发现感 | 弱——没有宝箱/事件/隐藏内容 | 1.0 |
| 重复游玩理由 | 4 职业差异 + 种子随机，但构筑单一削弱了重玩动力 | 1.5 |

### 4.6 UI/反馈/新手体验

#### 4.6.1 亮点

- i18n 体系（471 条双语条目）非常完整，专业术语和技能描述质量高
- TileRenderer 4 层渲染确保视觉层次清晰
- AudioRouter 提供了上下文感知的音频反馈
- HUD 显示 HP/资源/状态/日志

#### 4.6.2 需关注的问题

**数值反馈不够清晰**：
- 战斗日志只显示伤害数字，不显示伤害类型和抗性效果
- 玩家看不到"火球对这个怪造成了 FIRE 伤害 15，怪物有 20% 火抗，实际伤害 12"这种关键反馈
- 这与 DamageType 无感的问题叠加——即使以后加了怪物抗性，玩家也很难理解为什么同一个技能对不同怪伤害不同

**成长反馈缺失**：
- 升级时没有明确告知"你解锁了新技能 X"
- stat points 分配后的实际效果不直观（+1 STR 到底增加了多少攻击力？）

**死亡/失败理解度**：
- 死亡后有 GameOverScreen，但缺少"你为什么死了"的回顾
- 没有 death log 或 boss 战回顾

#### 4.6.3 UI/反馈评级

| 维度 | 当前状态 | 评分 |
|------|---------|------|
| 目标清晰度 | 中等——"杀 Boss"很清楚，但中间过程缺少子目标 | 2.5 |
| 数值反馈清晰度 | 弱——伤害类型/抗性/属性效果不透明 | 1.5 |
| 成长反馈 | 弱——升级/解锁/属性变化缺少强调 | 1.5 |
| 死亡可理解性 | 中等——知道自己死了，但不太知道为什么 | 2.0 |

### 4.7 系统联动性

#### 4.7.1 联动评估矩阵

| 系统 A → 系统 B | 是否联动 | 说明 |
|-----------------|---------|------|
| 战斗 → 掉落 | **否** | 杀怪不掉东西 |
| 掉落 → 装备 | **否** | 因为没有掉落 |
| 装备 → 战斗 | **理论上是** | 装备影响 Stats，但只有起始装备 |
| 升级 → 天赋解锁 | **有但过快** | level 5 就全解锁 |
| 天赋 → 战斗策略 | **是** | 天赋确实影响战斗方式 |
| DamageType → 怪物抗性 | **否** | 怪物无抗性 |
| Zone → 怪物池 | **数据上是** | YAML 定义了不同 zone 的怪物池，但 route 未实现 |
| Zone → 掉落池 | **否** | zone reward loot profile 未接入 |
| 资源类型 → 职业身份 | **是** | 四种资源回复策略创造了不同节奏 |
| 物品品质 → 成长感 | **否** | 物品品质系统未参与游戏流 |
| Objective → 奖励 | **数据上定义了** | 但 objective 完成后不给物品奖励 |
| Boss → 特殊掉落 | **否** | boss loot profile 存在但未调用 |

#### 4.7.2 核心诊断

**当前系统联动率约为 30%**——大多数系统都独立运作，没有形成网状互相驱动的关系。

最关键的断联是：**战斗 → 掉落 → 装备 → 战斗** 这条最基础的正反馈环完全不存在。这导致：
- 物品系统是孤岛
- 成长系统只有 XP/level 单一维度
- zone 差异只停留在怪物外观不同
- Boss 战缺少"打了就会有好东西"的期待感

#### 4.7.3 联动评级

| 维度 | 评分 |
|------|------|
| 战斗-奖励-成长三角 | 0.5（严重断裂）|
| 职业-天赋-装备三角 | 1.5（天赋有效但装备不参与）|
| Zone-怪物-奖励三角 | 1.0（数据就位但 runtime 断联）|
| 整体系统网络 | 1.5 |

### 4.8 玩法体验总评

| 维度 | 评分（1~5） | 一句话评价 |
|------|------------|-----------|
| 核心循环 | 1.5 | 关键奖励环节断裂，循环不成立 |
| 战斗体验 | 2.0 | 机制扎实但缺乏战术深度和差异化 |
| 成长与构筑 | 1.0 | 天赋全开、无成长节奏、构筑空间被压扁 |
| 奖励驱动 | 0.5 | 奖励系统几乎不存在 |
| 探索与重玩 | 2.0 | 有基础探索感但缺少惊喜和变化 |
| UI/反馈 | 2.5 | i18n 完善，但数值反馈和成长反馈不足 |
| 系统联动 | 1.5 | 大部分系统孤立运作 |
| **加权总分** | **1.6** | **功能骨架完整，体验远未达到"好玩"的门槛** |

> **判定：当前 Phase 2 版本不好玩。** 它拥有一个高质量的技术骨架和完整的数据定义，但核心游玩循环的关键环节（奖励、成长、构筑、系统联动）严重残缺。玩家在当前版本中体验到的是"探索+消耗性战斗+看数字涨"，而非 Roguelike 应有的"探索+发现+选择+构筑+挑战"。
