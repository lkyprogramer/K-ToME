# phase4 深度审查报告（Part 4/4）

## 6. 优化建议（续）

### P1：建议本阶段尽快处理

#### P1-1 为关键 reward/secret pool 增加局部去重护栏

- 问题本质：当前 loot profile 的全局平均差异足够，但局部关键 reward channel 仍然高度重叠。
- 影响范围：`loot/index.yaml`、`whitebox-loot-summary.json`、探索回报的记忆点、秘密奖励身份感。
- 优化目标：让玩家能明显感觉“这是 secret 奖励”“这是 route 奖励”“这是主线 cadence 奖励”，而不是只在预算大小上有差别。
- 具体改法：
  - 在 `tools` 白盒里新增 pairwise 局部 guardrail，而不是只保留 corpus average。
  - 规则上至少对“同 zone 内 reward vs secret”“cadence vs secret”建立更严格的上限。
  - 为 secret pool 预留少量专属 base item、slot bias 或 tag identity，不要求全部专属，但必须有能被玩家记住的特征。
- 优先级：P1
- 预期收益：隐藏内容的奖励价值更可感知，探索风险回报更鲜明。
- 可能副作用 / 风险：若做得过头，会让奖励池过于僵硬，牺牲掉落惊喜感。
- 需要同步修改：掉落配置、白盒阈值、phase4 报告口径，必要时更新 opt PR04 文档。

#### P1-2 扩大真实可激活的 build synergy 面，而不是只堆 affix 数量

- 问题本质：当前词汇库已经足够，但真正能在长局里成型的 synergy 太少，且集中在少数套路。
- 影响范围：装备词汇、职业成长、artifact/rare 的采用率、重复游玩动力。
- 优化目标：让更多职业在长局中能形成至少一种稳定可追求的装备协同，而不是只有少数 affix 真的“活着”。
- 具体改法：
  - 基于 `long-run-full.md` 的实际采用轨迹，找出被频繁发放但很少激活的 affix 族，减少纯装饰性组合。
  - 为 `arcanist`、`templar`、`vanguard` 等职业补 1~2 条更容易与职业主动技能形成闭环的装备协同，避免 `of_shadow` 一枝独秀。
  - 在体验指标中新增“按 profession 统计的 synergy activation breadth”，不要只看总次数。
- 优先级：P1
- 预期收益：玩家会更容易产生“这局我想围绕这个词缀再试一次”的念头。
- 可能副作用 / 风险：若不控制强度，可能产生新的最优解垄断。
- 需要同步修改：物品数据、可能的技能/被动说明、长局报告结构。

#### P1-3 把关键战术信息从 inspect/log 拉到更前台

- 问题本质：当前解释性成立，但关键信息消费仍偏二级通道。
- 影响范围：`client` HUD/inspect、地形利用率、Boss/精英可读性、新手失败可解释性。
- 优化目标：让玩家在不深度翻日志的情况下，也能及时知道“这个地形会电”“这个敌人有哪类变异”“这个被动刚刚改变了结果”。
- 具体改法：
  - 在 `TileRenderModel.kt` / `AsciiRenderModel.kt` 中，为当前目标敌人的变异、Boss 变体、地形危险性增加更短更硬的前台标记。
  - 对 `FoundationGameSession.kt` 已有的 `log.passive.*`、`log.search.*`、`log.hidden.*` 进行分层，把高战术价值事件提升优先级。
  - 不做大 UI 重构，只做低成本高显著度的状态徽记、目标栏摘要或地形提示条。
- 优先级：P1
- 预期收益：战术系统更容易被玩家实际利用，而不是只被熟练阅读者利用。
- 可能副作用 / 风险：提示过多会造成屏幕噪音，需要控制信息密度。
- 需要同步修改：客户端 UI、文案、必要时白盒截图基线。

#### P1-4 强化前期 zone 的重复游玩辨识度

- 问题本质：`greenwood_fringe` 当前差异度只是门槛线，不足以承担“开局就让玩家想重开”的责任。
- 影响范围：前期 replay hook、地图第一印象、隐藏入口记忆点。
- 优化目标：把早期 zone 从“技术上有变化”提高到“玩家主观上能明显感到变化”。
- 具体改法：
  - 给 `greenwood_fringe` 增加至少 1 组新的 pattern room 或 entrance layout family。
  - 让前期 hidden anchor 在布局或奖励类型上更鲜明，避免新手把其视为普通房间的随机扰动。
  - 在白盒指标中把 `distinctPatternRoomCount` 和 `distinctEntranceLayoutCount` 设为更高的目标，而不是满足最低差异门槛就算通过。
- 优先级：P1
- 预期收益：前 10 分钟的重复游玩价值明显提升。
- 可能副作用 / 风险：若只增加形状变化、不增加玩法变化，效果会有限。
- 需要同步修改：地图配置、白盒阈值、必要时 phase4 mapgen 文档。

### P2：可以排期但不应忽略

#### P2-1 调整隐藏内容的奖励呈现，让发现结果更“值得记住”

- 问题本质：现在隐藏内容系统已经存在，但“发现的情绪波峰”还不够高。
- 影响范围：隐藏奖励呈现、secret zone 的记忆点、探索情绪反馈。
- 优化目标：让玩家在发现隐藏内容时，获得比普通掉落更强的识别感。
- 具体改法：
  - 强化 `log.hidden.*` 与奖励 UI 的独特呈现。
  - 对 secret-only 的奖励族做更明显的命名、视觉或词汇差异。
- 优先级：P2
- 预期收益：提升探索满足感。
- 可能副作用 / 风险：若奖励本体没有差异，只改表现会显得虚。
- 需要同步修改：UI、文案、可能的物品模板命名。

#### P2-2 补一层“失败后能快速归因”的死亡/受挫反馈

- 问题本质：当前日志和 inspect 足以解释多数局部事件，但在连续受击、资源崩盘、隐藏触发失败等场景下，失败归因仍偏分散。
- 影响范围：新手留存、连续战斗挫败感、局后复盘效率。
- 优化目标：让玩家更容易回答“我为什么刚刚输掉这波交换”。
- 具体改法：
  - 对连续高伤害来源、关键被动触发、资源断档事件增加更聚合的短摘要。
  - 不必等 Phase5 的正式 death analysis 才补最小可用版本。
- 优先级：P2
- 预期收益：降低理解成本，提高继续尝试意愿。
- 可能副作用 / 风险：若摘要算法粗糙，可能误导归因。
- 需要同步修改：日志聚合、UI 文案、回放快照字段。

## 7. 可延后到后续阶段的问题

以下问题可以延后，但前提是先把前述 P0/P1 的体验债处理完。

### 7.1 更大规模的 content pack 作者体验与外部生态工具

- 为什么可以延后：Phase4 的核心目标是把 `ContentPackManifest` / `OverlayEntry` / overlay boundary 固定下来，而不是把完整创作生态做完。
- 当前是否需要兜底：需要保留现有 lint、manifest 校验、fail-fast 冲突报告；但不必现在扩成更完整的作者工作台。

### 7.2 更复杂的 meta-level 失败分析、重放诊断、Soak 运营化报表

- 为什么可以延后：这些更偏 Phase5 的稳定性、发布与 QA 收敛任务。
- 当前是否需要兜底：可以先做最小版失败摘要与 organic hidden metric，不需要现在就上完整 release 级 death analysis 平台。

### 7.3 更大规模的内容量扩张

- 为什么可以延后：当前最缺的不是“再多几十个内容对象”，而是现有内容是否能稳定产生区分体验。
- 当前是否需要兜底：要先修奖励分化与职业底盘问题，再扩内容；否则扩得越多，噪音越大。

## 8. 最终结论

### 8.1 当前 Phase4 是否达到了文档预期

**大体达到了。** 从系统合同、自动化 gate、白盒验证、资源密度、长局可打通性来看，当前版本已经完成了绝大多数 `docs/phase4/` 与 `docs/review/phase4/opt/PR` 的承诺内容。它不是“文档写得好，代码还没落地”的状态。

但如果把“文档预期”理解为“这些系统放进游戏里后是否已经形成稳定乐趣”，答案只能是：**达到了一半以上，但还没有彻底收口。**

### 8.2 当前版本是否已经“好玩”

**是，已经好玩。** 但这个“好玩”是建立在：

- 战斗语义层比过去完整得多；
- 地图、地形、精英、隐藏内容、掉落都有正式路径；
- 长局真的能跑通；
- 玩家已经能感知成长和发现；

而不是建立在“靠文档脑补未来会好玩”。

同时也必须直接指出：

- 它还没有好玩到可以无视当前体验债；
- 它的好玩更多来自“系统开始互相接上”，而不是来自“成长与奖励已经打磨到特别锋利”。

### 8.3 当前版本是否具备“耐玩雏形”

**具备。** Hidden content、精英变异、Boss 变体、掉落词汇、地形战术、长局路径已经足以支撑重复游玩雏形。

但这个耐玩雏形当前有三个薄弱点：

1. 职业与装备底盘分化不够稳。
2. 隐藏内容的自然发现驱动力没有被真实度量。
3. 局部奖励池仍有明显同质化问题。

所以它是“耐玩雏形成立”，不是“耐玩性已经打透”。

### 8.4 是否适合进入下一阶段开发

**不适合直接无条件进入。**  
如果“进入下一阶段”意味着把注意力主要切去 Phase5，而把当前 Phase4 的这几处体验债当成可后补项，我不建议这么做。

原因很直接：

- 装备底盘收敛会污染后续职业生态。
- 隐藏内容验收盲区会让你误判探索体验。
- 奖励池局部扁平会让后续内容扩张建立在错误奖励感知上。

这些都属于**当前阶段不修，后续只会更贵**的问题。

### 8.5 进入下一阶段前必须先补的内容

至少先补以下三项：

1. **职业/构筑感知的装备底盘修正**
   - 让不同职业不再被同一武器底盘系统性吞并。
2. **自然隐藏发现率指标与验收口径补齐**
   - 把 scripted correctness 与 organic experience 分开。
3. **关键 reward/secret pool 的局部去重护栏**
   - 让探索奖励真正有身份，而不是预算更大的同类物。

如果只允许再补一轮 Phase4 优化，我的建议顺序是：

1. 先修装备底盘收敛。
2. 再修 hidden metric 盲区。
3. 最后修局部奖励池扁平化。

一句话结论：

**当前 Phase4 已经从“系统完成”走到了“游戏开始成立”，但还没有走到“可以放心把核心体验债留给下一阶段”。它值得进入下一阶段的前提，不是功能更多，而是先把这几个最容易毁掉长期乐趣的地基问题修正。**
