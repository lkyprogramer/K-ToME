# Phase3 深度审查报告 (V2) — Part 2: 当前阶段玩法体验总评

---

## 4. 当前阶段玩法体验总评

### 4.1 核心循环（Core Loop）

#### 当前循环链路

```
主菜单 → 创角（职业+种族）→ 进入 shattered_outpost
  → 探索楼层（BSP地图）→ 遭遇怪物 → 战斗
  → 获取经验/掉落 → 升级（属性点+天赋点）
  → 清层→下楼梯 → Boss 战
  → 完成区域目标 → 选择路线（世界地图）→ 进入下一区域
  → 重复直到 abyssal_heart 或死亡
```

#### 循环完整性评估：**基本成立，但缺少关键"爽点"节拍**

**通顺的环节**:
- 地图生成 → 探索 → 战斗：BSP 生成器保证了合理的地图布局，怪物池按区域分配有差异化，战斗遭遇密度适中。
- 战斗 → 经验获取 → 升级：经验曲线 `level * 100 + 50` 合理（见 `ExperienceSystem.kt:15`），每级获得 2 属性点，每 2 级获得 1 天赋点，成长节奏平稳。
- 区域完成 → 世界地图选路：WorldGraph 的分支结构提供了真实的路线选择。

**薄弱的环节（按严重度排序）**:

1. **即时战斗反馈缺失（Critical）**
   - 问题：战斗结果目前仅通过文本日志（`messageLog`）反馈，没有伤害数字弹出、击杀确认动画、暴击特效等视觉/听觉强反馈。
   - 证据：`FoundationGameSession.kt` 中的 `addMessage()` 是唯一的战斗反馈通道；`RenderSnapshot` 的 `logEvents` 只输出文本 token。
   - 体验影响：玩家无法在 0.5 秒内直观感知"我打了多少伤害"、"是否暴击"、"敌人还剩多少血"——这直接摧毁了 roguelike 最重要的正反馈循环。
   - 对比参考：ToME 的浮动伤害数字 + 血条 + 击杀闪光是核心体验组件。

2. **掉落物缺乏惊喜感（High）**
   - 问题：当前楼层内掉落仅靠 `lootProfileId` 从预定义 item pool 随机生成，缺少"打怪直接掉装备"的即时满足感。
   - 证据：怪物的 `lootProfileId` 指向 `loot.foundation.common` / `loot.foundation.elite` 等通用 profile；掉落物品质分层（`ItemQuality`）存在但缺少掉落时的视觉区分。
   - 体验影响：玩家在楼层内战斗缺少"这次可能掉好东西"的期待感。

3. **楼层间奖励空白期过长（High）**
   - 问题：每个区域只有 2 层（`floorCount: 2`），Boss 通常在最后一层。但两层之间（层 1 清完→下楼梯→层 2）没有明确的阶段性奖励——只有升级时的属性/天赋点。
   - 证据：路线奖励（`RouteReward`）只在世界地图选路时兑现，不在楼层转换时触发。
   - 体验影响：楼层推进缺少"冲关成功"的里程碑感。

4. **探索动力递减（Medium）**
   - 问题：BSP 生成的地图布局虽然不同，但缺少让玩家主动探索的动力——没有隐藏房间、宝箱、事件遭遇、陷阱机制等探索型奖励。
   - 证据：`BspGenerator.kt` 只生成 Room + Corridor 结构；Interactable 系统存在但主要用于目标任务，不提供探索型惊喜。
   - 体验影响：玩家倾向于"找到楼梯直接下楼"，而不是"我想把整层探索完"。

#### 核心循环评分：6.5/10

> **"前 10 分钟问题"**：前 10 分钟（shattered_outpost 的 2 层）能撑住——新职业的初始技能组有新鲜感，第一个 Boss（bandit_captain）是明确目标。
> **"30 分钟问题"**：到 greenwood_fringe + 可选区域阶段开始失速——战斗模式开始重复，缺少新机制注入，掉落没有提升期待。
> **"60 分钟问题"**：到 deep_iron_pit 之后，如果构筑没有明显分化，动力显著下降。

### 4.2 战斗体验

#### 4.2.1 战斗决策空间

**积极面**:
- 4 基础职业确实提供了不同的战斗节奏：
  - **Vanguard**: STAMINA 经济，近战 burst + 防御切换（guard_stance + shield_bash）
  - **Arcanist**: MANA 经济，远程 AoE + 位移生存（fireball + blink）
  - **Rogue**: ENERGY（hit 恢复），隐匿 + 暴击 + 机动（stealth + backstab + roll）
  - **Templar**: POSITIVE_ENERGY（复合恢复），近战 + 治疗 + 净化（holy_strike + holy_light + purify）
- 资源轴差异化是真实的：STAMINA 的固定回复 vs ENERGY 的命中回复 vs MANA 的固定但昂贵，确实产生不同的战斗决策。
- 状态交互系统（92 种状态）提供了丰富的组合可能性。

**问题面**:

1. **普通怪物战斗无决策（Critical for feel）**
   - 绝大多数普通怪物（rat、bone_archer、bandit.sentry 等）的 AI profile 是 `ai.chase.basic` / `ai.kite.basic` / `ai.patrol.basic`，行为模式单一。
   - 怪物没有天赋/技能（`talents: {}` 对大部分怪物），战斗退化为"走到身边→普攻直到一方死亡"。
   - 证据：`data/monsters/index.yaml` 中 60 个怪物里，只有 Boss 级怪物（dungeon_lord、molten_giant、abyssal.guardian）和极少数精英有天赋。
   - 体验后果：**玩家 80% 的战斗时间花在无决策的普攻互刷上**，这是核心体验的致命缺陷。

2. **技能使用缺乏战术时机选择**
   - 当前技能系统支持冷却、资源消耗、距离、目标选择，但缺少"什么时候用更好"的战术维度——没有反击窗口、没有连击机制、没有技能组合触发（如"标记目标后爆发伤害 +50%"这类联动）。
   - 证据：`TalentResolver.kt` 和 `CombatPipeline.kt` 处理天赋使用，但没有"条件加成"机制——技能效果是固定的，不因使用时机或上下文变化。
   - 体验后果：技能使用退化为"冷却好了就按"，缺少策略深度。

3. **Boss 战是唯一有意义的战斗**
   - 4 个 Boss 遭遇战有多阶段、Telegraph 预警、AI profile 切换，这些都是好的设计。
   - 但 Boss 之间可能跨越 4-6 层楼和 30+ 分钟游戏时间——中间全是无决策的填充战斗。
   - 体验后果：Boss 战的高峰体验被大量平庸战斗稀释。

#### 4.2.2 战斗节奏

- **正常怪战斗太快**：普通 rat 只有 12-14 HP，玩家初始攻击 4-8 + 一次技能就能击杀，几乎没有过程。
- **Boss 战节奏合理**：Boss HP 78-150+，有阶段切换，有读条预警，节奏明显更好。
- **中间缺少"精英遭遇"的节奏层**：每个区域有 elitePools 定义，但精英怪与普通怪的差距不够大（elite HP 大约是 normal 的 1.5-2x），不足以构成独立的战斗节奏层。

#### 战斗体验评分：5.5/10

### 4.3 角色成长与构筑驱动

#### 4.3.1 成长系统拆解

| 成长维度 | 机制 | 频率 | 体感 |
|----------|------|------|------|
| 等级 | 经验值 → level up | 每 1-2 层一次 | 稳定，有全回复激励 |
| 属性点 | 2 点/级，STR/DEX/CON/WIL 四选一 | 每级 | 决策简单，选主属性即可 |
| 天赋点 | 1 点/2 级 | 每 2 级 | **过于稀缺** |
| 装备 | 地面拾取 + 商店购买 | 随机 | 缺少期待感 |
| 铭文 | 预装备 + 掉落 | 偶尔 | 26 种提供了一定选择 |

#### 4.3.2 天赋点稀缺度问题（Critical）

这是 Phase3 最大的构筑设计问题：

- **等级上限 20 级**（`ExperienceSystem.kt:29` 中 `level < 20`）
- **天赋点总量**: 每 2 级 1 点 → 总计约 10 个天赋点（1 级起始）
- **天赋树深度**: 基础职业 3 棵树 × 5-6 天赋/树 = 15-16 个天赋，每个天赋可升至 max 3-5 级
- **问题**: 10 个天赋点根本不够支撑任何有意义的构筑分化

具体分析：
- 4 个起始天赋各升 1 级就要 4 点（实际上它们初始就有 1 级，升到 2 级各需 1 点 → 4 点）
- 解锁 2 个新天赋各 1 点 → 2 点
- 剩余 4 点只能把 2 个天赋升到 3 级
- **玩家几乎没有真正的"选择不同 build 路线"的空间**

对比 ToME：ToME 50 级 × 丰富的 talent point 来源 → 能支撑 3-4 棵天赋树各深入到 3-5 级的多样构筑。

体验后果：
- "这局我想试另一种 build" 的动力几乎不存在
- 所有玩家的天赋分配最终趋同
- 洗点（RespecManager）功能形同虚设——没有足够的点数来做有意义的重分配

#### 4.3.3 属性点系统

属性点系统相对合理但缺少深度：
- 20 级 × 2 点/级 = 约 40 个属性点
- 4 个属性（STR/DEX/CON/WIL）的效用通过 StatsCalculator 映射到 attack/defense/accuracy/evasion/speed/maxHp/maxStamina 等派生值
- 问题：最优策略几乎总是"堆主属性"——Vanguard 堆 STR/CON，Arcanist 堆 WIL，Rogue 堆 DEX
- 缺少让"非最优分配"也有价值的机制（如混合构筑的 breakpoint 奖励）

#### 4.3.4 装备系统

装备系统的框架不错：
- 三槽位：Weapon / Off-hand / Armor
- 品质分层：ItemQuality 有分级
- 词缀系统：`AffixGenerator.kt` + `AffixDef` 提供随机词缀
- 材质系统：`MaterialDef` 影响基础数值

但体验问题：
- 装备获取途径单一（地面随机 + 商店固定），缺少"击败特定 Boss 必定掉某类装备"的定向追求
- 词缀效果虽然存在（HP regen、STA regen、crit bonus、talent bonus、damage vs tag、damage type bonus、resistance bonus），但缺少改变玩法的"构筑定义"级别的词缀
- 证据：`PassiveEffectResolver.kt` 中的 passive 效果都是数值修正，没有"改变技能行为"或"触发额外效果"的装备 passive

#### 成长与构筑评分：5/10

### 4.4 奖励驱动与掉落体验

#### 4.4.1 奖励层次分析

| 奖励类型 | 触发时机 | 内容 | 频率 | 玩家感知 |
|----------|---------|------|------|---------|
| 经验值 | 击杀怪物 | 15-300 XP | 每次战斗 | 数字增长，低感知 |
| 地面掉落 | 怪物死亡/地面刷新 | 随机装备/消耗品 | 不确定 | 无闪光/无品质预览 |
| 升级 | 经验达标 | 属性点+天赋点+全回复 | 每 1-2 层 | **仅有的明确正反馈** |
| 路线奖励 | 世界地图选路 | Shard + 保证物品 + 里程碑 | 每完成 1 区域 | 有选择感但间隔太长 |
| 商店 | 检查点 | 花 Shard 买装备/消耗品 | 每 2 区域 | 有经济决策但品类受限 |
| Boss 掉落 | 击败 Boss | 高品质装备 | 每 4-10 层 | **应是最强奖励但缺少仪式感** |

#### 4.4.2 奖励节奏问题

1. **"每场战斗都有价值"的感觉不成立**
   - 普通怪给 15-35 XP，升级需要 150-2050 XP，需要击杀大量普通怪才能升级
   - 普通怪掉落概率低且品质差
   - 玩家的内心独白会变成"又要清一堆垃圾怪"

2. **奖励曲线太平**
   - 从 shattered_outpost（推荐等级 1-4）到 abyssal_heart（推荐等级 15+），shard 奖励从 35 线性增长到 150
   - 缺少在关键节点（如击败第一个 Boss、进入新 biome）的奖励激增
   - 奖励曲线应该是指数型或阶梯型，不应该是线性的

3. **掉落缺少"闪光时刻"**
   - 当前没有"传说级掉落"这种让玩家截图发朋友圈的超稀有奖励
   - MilestoneReward 系统虽然支持保证 affix 品质，但触发频率太低（只在路线奖励时）
   - 证据：`RewardGenerationContext` 中的 `qualityFloor` 和 `minAffixCount` 只在 route reward 时配置，楼层内掉落没有这个机制

#### 奖励驱动评分：4.5/10

### 4.5 探索与新鲜感

#### 4.5.1 区域差异化

当前 10+ 区域的设计分为：
- **3 必经区域**：shattered_outpost（ruins）→ greenwood_fringe（forest）→ deep_iron_pit（mine）
- **4+ 可选区域**：bandit_camp、elven_ruins、molten_core、crystal_cavern、underground_river、abyssal_temple、abyssal_heart
- **biome 类型**：ruins、forest、mine、underground、abyssal — 5 种 biome 主题

**积极面**：
- 世界图的分支结构（WorldGraph）让不同 run 可以走不同路线
- 可选区域提供了额外的挑战和奖励
- 区域有 `specialMechanics` 字段（tutorial_lane、ambush_lane、ore_cart 等），暗示了差异化的玩法机制

**问题面**：
- `specialMechanics` 在代码中的实际实现程度存疑——`ZoneMechanicRuntime.kt` 只有 2.3K，主要是 intro hint key 的映射
- 区域间的实际战斗体验差异主要来自怪物池替换，不是地图机制变化
- BSP 地图生成没有区域特色参数——所有区域的地图看起来结构相似（Room + Corridor）
- 证据：`BspConfig` 是通用配置，`BspGenerator.kt` 没有区域特化逻辑

#### 4.5.2 重复游玩价值

| 因素 | 当前状态 | 支撑力度 |
|------|---------|---------|
| 职业选择 | 8 个职业（4 可玩）| 中等 — 4 次初始新鲜感 |
| 种族选择 | 3 个可用种族 | 低 — 种族差异较小 |
| 路线选择 | 2-3 条分支路线 | 中等 — 每次可走不同路 |
| 构筑分化 | 受天赋点限制 | 低 — 同职业不同 build 差距小 |
| 随机性 | seed 驱动地图+掉落 | 低 — 地图结构变化不影响策略 |
| Boss 挑战 | 4 个有设计的 Boss | 中等 — 是回玩动力之一 |

**当前版本的"再来一局"动力主要来自**：
1. 换一个职业
2. 走一条不同的路线
3. 尝试打败之前打不过的 Boss

**但缺少**：
- 每次 run 的随机事件（事件系统不存在）
- 随机商店或随机 NPC（商店是固定的）
- Roguelike 核心的"这局出了什么好东西，让我围绕它构建"的涌现性构筑体验

#### 探索与重玩评分：5.5/10

### 4.6 UI/反馈/新手体验

#### 4.6.1 信息呈现

**积极面**：
- 双语支持（en-US + zh-CN）的 i18n 框架完善
- HUD 显示了关键信息：HP、资源、等级、经验、属性、装备、天赋
- 检查模式（Inspect）可以查看敌人详细属性
- Telegraph 预警系统为 Boss 战提供了可视化提示
- 控制键提示文案在 i18n 中有完整覆盖

**问题面**:

1. **内部 token 外泄（PR-10 正在修复）**
   - 当前 world map 显示 `levelBandRef`（如 "lv3_5"）而不是 "推荐等级 3-5"
   - rescue tags 显示内部枚举（MOVEMENT/CLEANSING）而不是玩家语言
   - outcome summary 显示 raw zone id 路径
   - 这是 PR-10 的修复目标，当前 branch 正在进行中

2. **战斗信息过载 vs 不足并存**
   - 文本日志包含了详细的战斗结果，但需要玩家主动阅读
   - 缺少"一眼就能看到关键信息"的视觉层——如伤害数字悬浮、状态图标、Boss 血条进度
   - 证据：`StatusHudRenderer.kt` 只有 1.3K，`ResourceHud.kt` 5.4K — HUD 系统还比较基础

3. **新手引导缺失**
   - shattered_outpost 的 `specialMechanics` 包含 `tutorial_lane`，但实际教程内容不明确
   - 没有"按 1 使用技能"、"按 g 拾取物品"这类上下文提示
   - 控制键帮助文案虽然存在，但只是静态文本，不是交互式教程

4. **死亡原因理解困难**
   - 当前 outcome summary 有 `killerNameKey` 和 `outcomeReasonKey`，但缺少"你为什么输"的策略级反馈
   - 如 "你的火抗为 -25%，Boss 的火焰攻击造成了额外 25% 伤害" 这类帮助玩家学习的信息不存在
   - 证据：`OutcomeSummary` 的 `failureSummaryKey` 只区分 early/mid/late/finale 四个阶段，不提供具体的失败原因分析

#### UI/反馈评分：5/10

### 4.7 系统联动性

#### 4.7.1 联动关系图

```
战斗系统 ←→ 状态系统 ←→ 天赋系统        ★ 强联动
    ↕              ↕           ↕
 装备系统 ←→ 资源系统 ←→ 成长系统        ★ 中联动
    ↕              ↕           ↕
 经济系统 ←→ 世界系统 ←→ 目标系统        ★ 弱联动
```

#### 4.7.2 联动分析

**强联动（做得好的）**：
- 战斗↔状态↔天赋：天赋使用触发状态，状态影响战斗结果（stun 跳过行动、armor_break 降低防御、marked 提高命中），这是核心战斗三角，运行良好。
- 资源↔战斗↔天赋：不同资源轴（STAMINA/MANA/ENERGY）真实影响了技能使用节奏和战斗决策。

**中联动（存在但较弱的）**：
- 装备↔战斗：装备提供数值加成（attack、defense、HP regen、crit bonus），但缺少改变战斗行为的装备效果。
- 成长↔构筑：属性点和天赋点确实影响角色能力，但如前分析，天赋点过少导致构筑分化不足。

**弱联动（存在但几乎感知不到的）**：
- 经济↔构筑：Shard 经济只用于商店购买，不能用于强化装备、重铸词缀、解锁天赋等更深的构筑行为。
- 世界路线↔构筑：路线选择提供的 rescueTags（MOVEMENT/RECOVERY/ARCANE/PROTECTION 等）暗示了构筑方向，但实际奖励物品不一定匹配当前构筑需求——这是一个"有框架但还没填满"的联动点。
- 目标系统↔奖励：目标完成解锁下一区域，但目标本身不提供直接奖励——它是一个纯粹的门禁机制，不是奖励来源。

#### 4.7.3 断层问题

1. **"战斗是战斗，探索是探索"断层**
   - 战斗系统高度成熟，但探索系统几乎是空的
   - 地图上除了怪物、楼梯、任务交互物之外，没有其他可交互的对象
   - 探索不奖励战斗能力，战斗不影响探索效率

2. **"成长层与内容层脱节"断层**
   - 角色等级和属性在稳步增长，但面对的内容（相同类型的怪物 + 相同结构的地图）没有对应的丰富度增长
   - 到中期（level 5-8），角色能力增长了但体验没有相应的新鲜感注入

3. **"菜单层切换生硬"断层**
   - 从战斗地图→世界地图→商店→天赋分配→回到战斗地图，每次切换都是全新的 UI 状态
   - 缺少平滑的过渡和上下文保持

#### 系统联动评分：6/10
