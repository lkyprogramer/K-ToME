## 0. Goal Objective

Use this objective for a long-running `goal` style implementation loop:

```text
Drive K-ToME Dark UI/UX PR-08 from accepted resource-family direction to director-grade runtime evidence. Iterate resource candidates, compositor behavior, focused tests, crop reviews, golden evidence, packaged whitebox and final gates until the first-screen UI/UX reaches the PR-08 rubric without violating resource ownership, manifest authority, runtime layer boundaries or PR-07 close evidence.
```

The goal is not to make one screenshot pretty. The goal is to establish a
repeatable loop that can keep improving UI/UX while preserving the K-ToME
resource, manifest, renderer and verification contracts. After the accepted
`tileset.ruins` fixed proof slice, the loop has moved from the D8 topology
contract / hybrid / decomposition / AO-local-light / plate-fragment /
material-breakup band / source-cropped room plate V1 path to a formal
dedicated ruins topology source key,
`ui.map_stage.ruins.room_topology_source.pr08_demo`, plus repeatable mask
diagnostic owner boards. Source B first superseded source A because it was more
fragment-friendly and carried stronger distributed wall/light/floor structure
under topology bands. Source C then superseded B after a B/C mask diagnostic
and forced D8 golden recapture. Source D now supersedes C on the same key after
being generated as a more crop-safe topology atlas and judged through the
repeatable `client` mask owner artifact plus D8 runtime golden evidence. The
first bounded D follow-up has resolved the immediate branch as risky-path
source-alpha/compositor balance rather than another source-art regeneration:
dedicated topology-source crop bands now render at `0.42` instead of `0.36`.
The follow-up scope guard now keeps that stronger alpha limited to formal
dedicated topology sources; fallback family room-plate crops stay at `0.36` so
forest-edge and shadow-depths do not inherit the ruins alpha boost before they
have dedicated topology-source assets. This improves L-like, corridor-heavy and
tall-cross ruins risky-row readability while keeping the same resource keys,
manifest paths and gameplay overlay order. The next risky-path composition
packet adds internal seam dissolve fields over long visible shared seams in
`TOPOLOGY_RISK_HYBRID_PRESENTATION`; it is a structural room-level layer that
keeps hidden notches and boundary wall components intact while lowering the
tile/card-grid first read. It is still accepted-forward only
and does not make every topology-risk row match plate-safe authored-room
quality. This is not final Direction A production closure.

2026-06-02 review governance update: the loop must stop treating every
incremental `accepted-forward` packet as convergence. Before any all-map,
all-tileset or final Direction A closure, add a D9 real-procgen ROI gate that
measures `FULL_PLATE_SAFE` versus `TOPOLOGY_RISK_*` distribution from real
level-generation parameters, not only the fixed D8 demo probe. Also freeze the
accepted ruins proof slice unless a D9/packaged/director artifact proves a new
blocking regression. Further ruins topology-risk alpha, seam, fog, line-weight,
single-cell rectangle or same-key source polish is blocked by default until the
D9 distribution and ROI decision decide whether Direction A should continue,
converge to hybrid-first composition, or stop.

### 2.3 Agent-Owned Foundational UI/UX Decision Protocol - 2026-05-31

The PR-08 loop now uses autonomous agent decision-making for UI/UX direction,
resource candidates, prototype promotion, map-slice closure, surface priority
and art-regeneration loops. The user has delegated these decisions so the agent
can keep moving without repeated human gates.

The decision standard is stricter than "make the screenshot look different":

1. Prefer bottom-up UI/UX fixes: authored room art plates, resource-family
   replacement, room composition, information hierarchy, readable interaction
   overlays and stable asset authority.
2. Reject local numeric patching as the default strategy: alpha tweaks, seam
   width changes, more rectangles, fog overlays, same-key texture nudges and
   per-cell masking cannot be accepted as a major solution unless they are
   clearly subordinate to a stronger resource/composition change.
3. Two consecutive micro-passes that leave the same first-read problem mean the
   agent must reclassify the blocker and switch technique, usually toward new
   art resources or a presentation-layer boundary.
4. A decision is valid only when it names the root cause class, evidence path,
   selected route, rejected alternatives, rollback path, tests/gates and
   remaining risk.
5. Historical `awaiting-lky-decision` wording in older entries should be read
   as `agent-recorded-decision-required` for future work.

Decision hierarchy for future PR-08 work:

1. Diagnose the root UI/UX layer first: first-read hierarchy, player attention,
   interaction affordance, marker readability, surface priority or resource
   authority.
2. Choose the lowest structural fix that can remove that root cause: surface
   hierarchy, presentation-model boundary, resource family, room art plate,
   state grammar, layout composition or manifest/owner route.
3. Use renderer code and numeric tuning only to integrate the chosen structural
   route, preserve readability or remove obsolete pass debt. They are not
   allowed to become the main answer to a known resource/composition blocker.
4. Treat hash drift, RGB distance, changed-ratio, line contrast and screenshot
   difference as diagnostics only. They cannot accept a major UI/UX decision
   without fixed-crop A/B evidence and root-cause classification.
5. Before accepting a major route, explicitly state why it is a foundational
   improvement rather than another parameter patch. If that statement cannot be
   made, reclassify the blocker or generate a stronger candidate.
6. For every family close point, require a bounded stop line before more
   same-technique polish. A crop is closeable only if the first read is room
   material before tactical grid, wall/door/light structure remains coherent,
   runtime markers stay clearer than the environment, and the packet names
   which visible deficiencies are intentionally frozen for the next phase.

Agent-owned major decisions:

1. selecting, rejecting or replacing the active map aesthetic direction
2. accepting a room art plate candidate as the next runtime prototype target
3. promoting an exploration image into the existing approved resource route
   when no schema/public-contract change is needed
4. deleting, disabling or replacing old decorative renderer passes that are
   demonstrably superseded by the art plate and covered by tests
5. declaring `tileset.ruins` map-stage closure from runtime evidence
6. deciding whether to close the 2026-06-02 `forest_edge`, `mine` and
   `shadow_depths` proof into packaged/all-map evidence, or to record remaining
   family/topology gaps as follow-up work
7. pivoting between map, right panel, bottom HUD, inventory and talent work
   based on which surface dominates the first-read quality gap
8. accepting Direction B or another fallback only if Direction A evidence shows
   the authored-room route is structurally wrong
9. deciding whether the random-seed generalization probe keeps Direction A as a
   fixed full-room plate, constrains it behind topology mask / deterministic UV
   work, pivots it into a hybrid topology-following component route, or rejects
   the fixed-plate approach for procedural maps

Repository red lines still apply:

1. changing public schema, manifest schema, atlas/region schema, save/replay
   contract or content-pack contract still follows AGENTS.md high-risk rules
2. deleting tracked files or large asset families requires explicit risk
   accounting and a reversible path
3. runtime code must not load from `UI/review/...`, generated-image folders or
   machine-local absolute paths
4. final golden rebaseline is allowed only after the final runtime packet,
   focused tests and owner/resource gates support the chosen route
5. all-map or production Direction A closure is blocked until the random-seed
   generalization probe has an explicit recorded verdict

Decision packet requirement:

1. For every major decision, write a compact decision packet or log entry with
   candidate paths, comparison board, selected option, reject reasons,
   required deletions, owner/gate impact and rollback path.
2. Do not stop merely to ask lky for visual preference. Continue with the
   evidence-backed route unless a repository hard red line or impossible
   ambiguity is hit.
3. A metric-only improvement is never sufficient for a major decision. Fixed
   crop A/B evidence and root-cause classification are the acceptance source.
4. The packet must include a `why-not-micro-tuning` note. It should explain why
   the selected route changes the underlying resource, presentation model,
   information hierarchy or surface ownership instead of merely changing alpha,
   seams, line weight, fog, rectangles, draw order or same-key texture details.
5. For PR08 map-stage packets after 2026-06-02, the packet must also include a
   `why-not-fixed-crop-overfit` note. It should explain whether the evidence
   proves more than the current fixed crop, and if not, why the work is still a
   bounded probe rather than a closure claim.

## 4. Iteration Strategy

Exit from this loop only when the visual direction for a resource family is accepted or rejected with evidence.

### 4.2 Resource Candidate Loop

Use when the active blocker is an authored resource family: floor material,
wall material, reusable UI chrome, sheet quality, manifest ownership or
resource resolver coverage.

This loop is the primary quality path only for resource-owned blockers. It must
not degenerate into minor edits of the current tile plus renderer compensation.
When the latest log classifies the blocker as haze, rectangular dark field,
room-level hierarchy or cross-cell structure, use the Runtime Compositor Loop
instead. When a resource family is visually blocking director acceptance, run a
candidate batch:

1. produce at least three distinct resource candidates for the active family
   unless the log records a concrete blocker
2. include a conservative candidate, a material-depth candidate and a stronger
   style candidate; these must not be only parameter tweaks of the same failed
   generation technique
3. generate a tiling/contact preview plus the same runtime crop set for each
   candidate
4. compare every candidate against `UI/UI-demo-new.png` and the previous best
5. reject candidates that only improve one artifact while worsening first-read
   runtime quality
6. if two candidates using the same generation technique fail for the same
   blocker, the third attempt must change technique, such as a new art
   generation mode, autotile/variant strategy, room-scale decal/AO split or
   a new target prompt/art-direction pass, rather than only tuning parameters

Required before mutation:

1. identify owner row and target key
2. record supersession and rollback if replacing PR-02-2 resources
3. confirm output path is repo-relative
4. confirm no schema change is needed

Allowed resource generation scope:

1. floor and wall resources may be regenerated as a family, not only patched
   from existing PNGs
2. right panel, slot chrome and bottom deck chrome may be regenerated once the
   map first-read blocker is no longer dominant, or earlier if full-screen
   cohesion is the blocker
3. generated images must remain text-free and key-free; labels, numbers,
   hotkeys and item semantics stay runtime-owned
4. single-tile floor candidates must prove acceptable 4x tiling behavior before
   runtime integration; otherwise generate additional variation or move the

### 4.3 Runtime Compositor Loop

Use when changing `TileRenderer`, `DemoShellRenderer` or focused renderer
behavior, and when the active blocker is runtime composition: broad haze,
rectangular dark field, room-level hierarchy, local light pools, marker
readability or deterministic cross-cell structure.

This loop is the primary quality path for composition-owned blockers. It may
adjust layer ordering, marker readability, light/dark hierarchy and
deterministic room-scale composition. It must not compensate for weak assets by
adding more per-cell micro-rectangles, seams or fog.

Required before code:

1. state which layer is being changed
2. state which gameplay markers must remain readable
3. avoid second visibility authority
4. avoid new general-purpose renderer helpers unless they remove real complexity

Hard stop rules:

1. if two consecutive compositor iterations still leave the map grid-forward in
   director crops, reclassify the blocker before continuing; return to the
   Resource Candidate Loop only when evidence says the blocker is resource-owned
2. if a compositor change makes floor/wall quality depend on hidden overlays
   rather than authored resources, reject it even when tests pass
3. if marker readability conflicts with floor/wall polish, keep marker
   readability and move the visual quality work back to resources
4. if resource and compositor loops bounce the same blocker back and forth three
   times, stop local patching and record the next technique-change before
   continuing
5. deterministic room-scale AO, soft dark fields, local light pools and
   cross-cell decals are allowed in this loop; they must be keyed by stable map
   seed and world coordinates and must not encode text, loot, telegraph
   semantics or resource authority

The agent must prepare and own the director review packet using the rubric, A/B

Acceptance requires visible A/B improvement over the previous best in the
blocking area, plus root-cause evidence that the chosen route improves the

Minor implementation iterations can continue without a new packet when they

Major decisions require an agent-owned decision packet, not a human wait state.

These checkpoints do not restore repeated human gates. They exist only where the
decision is product ROI or aesthetic stop-line rather than a local technical

## 5. Gate Policy

The goal loop intentionally separates UI/UX iteration from final gate closure.

| Stage | Gate posture | Reason |
| --- | --- | --- |
| Visual exploration | no heavy Gradle by default | avoid wasting time on throwaway images and direction probes |
| Resource candidate | run owner/resource gates | resource mutation can break manifest and packaged assets |
| Runtime compositor | run focused renderer tests first | code changes need behavior guardrails before visual review |
| D9 procgen ROI probe | run distribution/statistics probe before broad Direction A rollout | the full-room plate path is valuable only if the real procgen shape distribution supports the cost |
| Director review / golden acceptance | run targeted golden slice only after the agent accepts the major visual direction, then broader golden | screenshot hashes are acceptance artifacts, not exploration tools |
| Final close | run full listed PR-08 gates | close must be reproducible, packaged and owner-routed |

This means: yes, early UI/UX iterations can temporarily avoid heavy gates. No, runtime/resource integration cannot bypass its owner gates. Final acceptance always requires the full closure ladder.

Resource candidate batches should spend time on visual generation and A/B crop
review before broad gates. Once a candidate is integrated into runtime resources,
the owning resource gate is mandatory.

Expected-fail golden hash drift is not a success signal during exploration.
Record hashes only to prove baselines were not silently updated; major visual
progress is decided by an agent-owned fixed-crop A/B decision against the
previous best and the target reference.

## 6. Director Rubric

Use this rubric after every candidate screenshot.

| Area | Pass condition | Blocking fail |
| --- | --- | --- |
| First read | center map is dominant; right and bottom support it | right panel, bottom deck or fog steals first read |
| Floor | room-level floor reads as authored worn stone; no single 32px tile motif dominates first read | repeated debug grid or muddy overlay dominates |
| Wall | reads as thick masonry boundary | wall reads as thin border or noisy rubble wallpaper |
| Darkness | soft non-rectangular dark field and room-level AO frame the dungeon | uniform black/green rectangle or second visibility authority |
| Light | local warm pools focus attention without washing the room | broad amber haze hides material or markers |
| Player/enemy/loot | gameplay markers remain clearer than material | actor, loot, telegraph or selection is buried |
| Telegraph | danger marks are readable over the new floor/wall | red/green overlays disappear or look decorative |
| Right panel | equipment/inscription/backpack read as one workbench | slots float as unrelated icons or labels dominate |
| Bottom deck | hero/action/log form one control console | deck splits into unrelated panels or text crowding |
| Text | Chinese labels and hotkeys remain legible | texture, glow or crop buries runtime text |
| Resource contract | every visual family maps to key, sheet, consumer and test | image requires new schema, full-screen art or baked text |

Quantitative companion rules:

1. Rubric rows are not allowed to collapse into a vague `improved` verdict. Each
   packet must record `pass`, `blocking-fail`, `accepted-forward-only` or
   `freeze` for the active rubric rows.
2. A packet that is accepted-forward but still leaves the same active blocker
   below the required rubric threshold counts toward the escalation ladder
   unless it also closes a named prerequisite that unblocks a different
   technique.
3. For Direction A topology work, D8/D9 evidence must report
   `FULL_PLATE_SAFE` count, topology-risk count and the observed failure reason
   distribution. Do not infer all-map value from a fixed crop or from a small
   hand-picked board.

## 9. Completion And Blocked Rules

Mark the goal complete only when:

1. PR-08 director evidence exists and is explicitly accepted in an agent-owned
   decision record.
2. resource readiness has no blocking findings.
3. focused client tests pass.
4. golden screenshot evidence passes.
5. packaged whitebox is complete or a real blocker is documented.
6. `maintainabilityLint` and `verifyChanged` pass.
7. runtime parity record and iteration log are updated.
8. every major direction, room-plate promotion, large renderer deletion,
   surface freeze and final closure decision has a recorded agent-owned
   decision.

Escalation ladder:

1. `failure` includes failed commands, failed focused assertions, failed rubric
   rows, D8/D9 distribution evidence below the active threshold, or an
   accepted-forward packet that leaves the same active blocker below threshold
   without closing a named prerequisite.
2. `accepted-forward` must record its failure-counter impact: `counts-as-progress`,
   `counts-as-failure`, or `freeze-no-more-local-polish`.
3. two failures using the same technique require a technique change, not another
   parameter tweak
4. three repeats of the same blocker require a recorded technique-change
   decision, such as switching resource generation mode, changing compositor
   structure, or deferring to the chrome sprint when the map is no longer the
   dominant blocker
5. after a freeze decision, do not continue the frozen family with alpha, seam,
   fog, line-weight, single-cell rectangle, source or same-key texture tweaks
   unless a new artifact proves a regression or a new active blocker.
6. mark the goal blocked only when the exact failure shows there is no
   meaningful next local action without external input

Mark the goal blocked only when:

1. the escalation ladder above has been followed
2. there is no meaningful next local action without external input
3. the blocker is recorded with exact failed command, artifact path and the missing external input, if any

Do not mark the goal complete because a single screenshot looks better. Do not mark it blocked because a visual iteration is slow.
